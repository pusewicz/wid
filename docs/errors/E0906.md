# E0906: compile-time-only code runs at run time

A method that the program runs uses a value that exists only while compiling.
`Type` values (a type used as a value, like the `t` in `t.fields`) and
reflection (`T.fields`, `T.methods`) describe the program's types to
compile-time code; the built program has no such values. Neither has it
`Code` values, which macros take and build with `quote`, nor `Symbol`
values, names like `:hp` that macros splice into code. A method that uses
any of them, or calls a method that does, can only run inside `comptime`
(or, for `Code`, in a macro).

The error points at the run-time call and marks the compile-time-only use
inside the callee. When the call passes a type, the help names the
`type_info` call that describes that type while the program runs.

The same code reports `type_info` of `Type`, or of a record that holds one
(like `FieldInfo`): `type_info` returns a table the program keeps at run time,
and a `Type` can't be part of it.

## Example

```wid
struct Point
  x: Int
  y: Int
end

def field_count(t: Type) -> Int
  t.fields.size
end

def main
  puts field_count(Point)
end
```

```text
error[E0906]: `field_count` works only at compile time
  --> main.wid:11:3
   |
 7 |   t.fields.size
   |     ------ reads a `Type`, which exists only while compiling
...
11 |   puts field_count(Point)
   |   ^^^^^^^^^^^^^^^^^^^^^^^ `main` calls it when the program runs
help: call it while compiling instead, like `x = comptime field_count(…)`
help: to describe `Point` while the program runs, use `type_info(Point)`: a `^TypeInfo` with its `name`, `size`, `align`, `fields` and more
   = see `wid explain E0906`
```

## How to fix

Run the method while compiling and use its result:

```wid
struct Point
  x: Int
  y: Int
end

def field_count(t: Type) -> Int
  t.fields.size
end

POINT_FIELDS = comptime field_count(Point)

def main
  puts POINT_FIELDS
end
```

Or describe the type while the program runs with `type_info(T)` (or
`type_info(x)` for the type of a value). It returns a `^TypeInfo`, whose
`fields` have a `name`, a `type` and an `offset` like `T.fields` does:

```wid
struct Point
  x: Int
  y: Int
end

def field_count(t: ^TypeInfo) -> Int
  t.fields.size
end

def main
  puts field_count(type_info(Point))
end
```

## `type_info` of a `Type`

```wid
def size_of_type(t: Type) -> Int
  type_info(t).size
end

SIZE = comptime size_of_type(Int)

def main
  puts SIZE
end
```

```text
error[E0906]: `type_info` can't describe `Type`, which exists only while compiling
 --> main.wid:2:13
  |
2 |   type_info(t).size
  |             ^ this `Type` value exists only while compiling
  = note: `type_info` returns a table the program keeps while it runs
help: to describe the type it holds, read it while compiling with `t.name`, `t.size`, `t.align` and `t.fields`, or pass the type itself, like `type_info(Ball)`
  = see `wid explain E0906`
```

`type_info(t)` describes the static type of `t`, which is `Type`. Read the
type `t` holds with `t.size`, or pass the type itself: `type_info(Int).size`.

## A `Symbol` or `Code` at run time

```wid
def describe(s: Symbol) -> String = s.to_s

def main
  puts describe(:hp)
end
```

```text
error[E0906]: `describe` works only at compile time
 --> main.wid:4:3
  |
1 | def describe(s: Symbol) -> String = s.to_s
  |     -------- uses `Symbol` values, which exist only while compiling
...
4 |   puts describe(:hp)
  |   ^^^^^^^^^^^^^^^^^^ `main` calls it when the program runs
help: call it while compiling instead, like `x = comptime describe(…)`
help: while the program runs, name things with a `String` or an enum; `sym.to_s` gives a symbol's name as a `String` while compiling
  = see `wid explain E0906`
```

Compute the name while compiling, `NAME = comptime describe(:hp)`, or keep a
`String` from the start. A `Code` value only ever passes between macros: call
the macro where its code should go.
