# E0902: macro expansion failed

A `macro def` runs at compile time. It receives types, AST and symbols, and
returns code built with `quote do … end`, with `#{}` splicing values in. This
error means a macro failed: it rejected its arguments, hit a `panic` or a
failed `assert`, or produced code that is not valid where it was called.
`attr_reader` and `attr_accessor` are planned as `core` macros, so their
mistakes will be reported the same way.

This compiler version does not expand macros yet, so it never reports E0902.
A `quote` block is reported as E0001 ("this expression is not implemented
yet"), and so is a macro call inside a type such as `attr_reader :hp` ("a
macro call inside a type is not implemented yet").

## Example

`attr_reader` given a symbol that names no field of the struct:

```wid
struct Player
  hp: Int = 100
  attr_reader :health
end

def main
  player = Player.new
  puts player.health
end
```

## How to fix

- Check the arguments against what the macro expects. Here each symbol must
  name a field of the struct.
- If you wrote the macro, check what it returns. The `quote` block must form
  valid declarations or statements at the call site, and every `#{}` splice
  must produce a name, type or value of the kind used there.
- A macro runs like `comptime` code, so its `panic` and `assert` messages are
  reported here. Use them to explain bad arguments to the macro's users.

```wid
struct Player
  hp: Int = 100
  attr_reader :hp
end

def main
  player = Player.new
  puts player.hp
end
```
