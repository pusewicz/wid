# E0406: macro code in an operand has a `defer`

A macro's code runs in place of the call, and a `defer` in it runs when the
block around the call ends. Some operands don't run once with the statement
around them, so no block ends when such a `defer` should run:

- the right side of `&&` or `||`, which runs only when the left side doesn't
  decide the result;
- the value of `||=` or `&&=`, which runs only when the assignment happens;
- `type_info`'s operand, which is checked but never runs;
- a `while` or `until` condition, which runs again on each test of the loop.

The code a macro generates there runs with the operand, so a `defer` in it is
an error at the call, which also marks the `defer` in the `quote`. The
`defer`'s body is still checked.

## Example

```wid
macro def logged(value: Code) -> Code
  quote do
    defer puts("checked")
    #{value}
  end
end

def ready?(count: Int) -> Bool
  count > 0 && logged(count < 10)
end

def main
  p ready?(3)
end
```

```text
error[E0406]: the code `logged` generates in the right side of `&&` has a `defer`
 --> main.wid:9:16
  |
9 |   count > 0 && logged(count < 10)
  |                ^^^^^^^^^^^^^^^^^^ `logged` expands here, in the right side of `&&`
 ::: main.wid:3:5
  |
3 |     defer puts("checked")
  |     --------------------- this `defer` would wait for the end of the block around it
  = note: a `defer` runs when its block ends, but the right side of `&&` runs only when the left side is true, so the end of the block around it can't tell whether the `defer` was reached
help: call `logged` in a branch of an `if` instead, whose end runs the `defer`; or, if its code may always run, as a statement of its own before this line (`v = logged(…)`), and use `v` here
  = see `wid explain E0406`
```

## How to fix

- To run the code only when the operand would, call the macro in a branch of
  an `if`: a branch is a block, and its end runs the `defer`.
- If the code may always run, call the macro as a statement of its own before
  the operand (`in_range = logged(count < 10)`) and use the variable there.
- For `type_info`, store the macro's value in a variable and describe that.
- For a loop condition, test it in the body of a `loop` instead
  (`break unless logged(…)`): the `defer` runs when each pass ends.

```wid
macro def logged(value: Code) -> Code
  quote do
    defer puts("checked")
    #{value}
  end
end

def ready?(count: Int) -> Bool
  if count > 0
    logged(count < 10)
  else
    false
  end
end

def main
  p ready?(3)
end
```
