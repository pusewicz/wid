# E0915: macro named like an operator

Operators are methods of types: `a + b` calls the `+` method of `a`'s type
(or a package-level `def +` that takes both operands), and the program runs
it. A macro only expands where it is called by name, so a `macro def` named
like an operator (`+`, `==`, `[]`, unary `-`, …) could never be used. For the
same reason an operator's `overload` set can't list a macro.

## Example

```wid
struct Money
  cents: Int
end

macro def +(a: Code, b: Code) -> Code
  quote do
    Money.new(#{a}.cents + #{b}.cents)
  end
end

def main
  p Money.new(150) + Money.new(25)
end
```

```text
error[E0915]: a macro can't be named like the operator `+`
 --> main.wid:5:11
  |
5 | macro def +(a: Code, b: Code) -> Code
  |           ^ operators are methods, not macros
  = note: `a + b` calls a method of `a`'s type, or a package-level `def`, when the program runs, while a macro only expands where it is called by name
help: give the macro a name and call it by that name, like `add(…)`
  | macro def add(a: Code, b: Code) -> Code
help: to keep the operator, define it with `def +` in the left operand's type, or at package level; its body may call a macro
  = see `wid explain E0915`

error[E0307]: `+` is not defined for `Money`
  --> main.wid:12:5
   |
12 |   p Money.new(150) + Money.new(25)
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ both sides are `Money`
help: define the operator on `Money`: `def +(other: Money) -> Money`
   = see `wid explain E0307`
```

## How to fix

- To keep the operator, define it with `def`, as a method of the left
  operand's type (or at package level, taking both operands). Its body may
  call a macro.
- To keep the macro, give it a name and call it by that name, like
  `add(a, b)`.

```wid
struct Money
  cents: Int

  def +(other: Money) -> Money = Money.new(@cents + other.cents)
end

def main
  p Money.new(150) + Money.new(25)
end
```
