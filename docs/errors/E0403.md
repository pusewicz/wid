# E0403: `guard` on a value that cannot fail

`guard name = expr` needs a value that can fail: an optional `T?`, or a result
whose last value is an `Error`. Here the value has a plain type, so the `else`
branch could never run. The other form, `guard cond else … end` with a `Bool`
condition, is fine.

## Example

```wid
def double(x: Int) -> Int = x * 2

def main
  guard d = double(4) else
    return
  end
end
```

```text
error[E0403]: `guard` needs a value that can fail, found `Int`
 --> main.wid:4:13
  |
4 |   guard d = double(4) else
  |             ^^^^^^^^^ this always succeeds
  = note: guard works on optionals (`T?`), results ending in an `Error`, and `Bool` conditions
help: assign the value directly, like `name = value`, and drop the `else` branch
  = see `wid explain E0403`
```

The same code reports two related mistakes:

- `if d = double(4)`: the `if v = …` form also needs an optional, and the
  error reads `` `if d = …` needs an optional, found `Int` ``.
- `guard v = find(1) else |err|` where `find` returns `Int?`: an optional
  carries no error value, so there is nothing to bind to `err`.

## How to fix

- Assign the value normally: `d = double(4)`.
- If the function should be able to fail, change its return type to `T?` or
  `(T, Error)`.
- To check a condition, use the `Bool` form: `guard d > 0 else … end`.
- On a `guard` over an optional, drop the `|err|` binding.

```wid
def double(x: Int) -> Int = x * 2

def main
  d = double(4)
  guard d > 0 else
    return
  end
  puts d
end
```
