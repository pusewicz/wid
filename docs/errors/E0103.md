# E0103: invalid number literal

A number literal is malformed. Its digits are not valid for its base (`0b102`,
`0xZZ`), it is too long for any integer type, or it has a suffix. Wid number
literals have no type suffixes such as `f`, `u` or `i64`. A literal takes its
type from where it is used, so the type goes on the variable, parameter or
constant instead. The fix for a suffix removes it.

## Example

```wid
def main
  speed = 1.5f
  puts speed
end
```

```text
error[E0103]: number literal with suffix `f`
 --> main.wid:2:14
  |
2 |   speed = 1.5f
  |              ^ unexpected suffix
  = note: Wid number literals have no suffixes; the type comes from context, like `x: F32 = 1.5`
help: remove the suffix
  |   speed = 1.5
  = see `wid explain E0103`
```

## How to fix

- Drop the suffix and declare the type: `speed: F32 = 1.5`.
- Use only the digits the base allows: `0b` takes 0 and 1, `0o` takes 0 to 7,
  and `0x` takes 0 to 9 and `a` to `f`.
- Group digits with `_`: `1_000_000`, `0xFF_FF`.
- To change the type of an existing value, convert it with `.to(T)`.

```wid
def main
  speed: F32 = 1.5
  puts speed
end
```
