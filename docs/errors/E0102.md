# E0102: unterminated string literal

A string literal starts but never ends. Strings may span several lines, so a
missing closing quote pairs up with the next quote in the file, and the error
may point at a quote further down: look for the first string on or above that
line that is not closed. When no quote follows at all, the compiler ends the
string at the end of the line it starts on, so the code after it is still
checked, and the fix adds the closing quote there.

The same code is used for an interpolation `#{` whose `}` is missing from its
line ("unterminated string interpolation"). The fix adds the `}` before the
string's closing quote. It is also used for a splice `#{` in a `quote` whose
`}` is missing from the rest of the file ("unterminated splice"); the fix
adds the `}` after the last code on the splice's line.

## Example

```wid
def main
  puts "hello
end
```

```text
error[E0102]: unterminated string literal
 --> main.wid:2:8
  |
2 |   puts "hello
  |        ^ string starts here
help: add a closing `"`
  |   puts "hello"
  = see `wid explain E0102`
```

The string swallowed the final `end`, so the compiler also reports E0106 for
`def main`. Fix the string first.

## How to fix

- Add the closing quote where the string should end.
- Close every interpolation: `"hp: #{hp}"`.
- To put a quote inside a string, escape it (`"say \"hi\""`) or use the other
  quote style (`'say "hi"'`).

```wid
def main
  puts "hello"
end
```
