# E0329: type is too large

A type takes more memory than the C compilers Wid uses accept for one
object. Clang rejects an array of `2^61` bytes or more, so a Wid type can
take at most 2305843009213693951 bytes (`2^61 - 1`, two exbibytes), and an
array can have at most that many elements. No machine has that much memory,
so reaching the limit usually means a length was computed wrong, such as a
shift by too many bits.

The error is reported where the type is written: an array, optional or tuple
type, the field that takes a struct over the limit, a union variant that
does with the union's tag, or an array literal. For a field of a generic
struct, it names the instance (`in Grid(…)`), and for a call of a generic
method whose instance would return such a type, it points at the call.

## Example

```wid
def main
  table: [1 << 61]I64
  table[0] = 1
  p table[0]
end
```

```text
error[E0329]: this type is too large
 --> main.wid:2:10
  |
2 |   table: [1 << 61]I64
  |          ^^^^^^^^^^^^ `[2305843009213693952]I64` would take 18446744073709551616 bytes
  = note: a type can take at most 2305843009213693951 bytes (2^61 - 1), the most that every supported C compiler accepts
help: use a smaller length; for data sized at run time, allocate a slice with `alloc([]I64, n)` or use a `[dynamic]I64`
  = see `wid explain E0329`
```

## How to fix

- Use a smaller length.
- For data whose size is only known at run time, allocate a slice with
  `alloc([]I64, n)` (and `defer free(table)`), or grow a `[dynamic]I64`.
- Keep the large part of a struct behind a pointer or in a slice, so the
  struct itself stays small.

```wid
def main
  n = 1 << 20
  table = alloc([]I64, n)
  defer free(table)
  table[0] = 1
  p table[0]
end
```
