# E0106: missing `end`

A block opened with `def`, `if`, `while`, `do`, `struct`, `case` or another
keyword has no matching `end`. Instead of blaming the end of the file, Wid uses
indentation to find where the `end` is most likely missing. It points at the
opener, and at any `end` that seems to close the wrong block.

## Example

```wid
def main
  if true
    puts "yes"

  puts "after"
end
```

```text
error[E0106]: this `if` is never closed
 --> main.wid:2:3
  |
2 |   if true
  |   ^^ `if` opened here needs a matching `end`
...
6 | end
  | --- this `end` is indented like an outer block, so it probably closes that instead
help: the indentation suggests the `end` belongs here
  |   end
  |   puts "after"
  = see `wid explain E0106`
```

## How to fix

- Add `end` where the help shows it, at the opener's indentation.
- Check blocks opened in the middle of a line. A `do` block needs `end`, and a
  `{` block needs `}`.
- Postfix `if` and `unless` (`return if done`) take no `end`. The block forms
  do.
- An unterminated string (E0102) can swallow an `end`. Fix that first.

```wid
def main
  if true
    puts "yes"
  end

  puts "after"
end
```
