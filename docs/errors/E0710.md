# E0710: unknown sanitizer

<!-- command: build main.wid -file -sanitize:adress -->
<!-- fix-command: build main.wid -file -sanitize:address -->

`-sanitize:` builds the program with one of the C compiler's sanitizers,
which check it while it runs and report what went wrong at the `.wid` line
it happened on (with `-debug`). Wid supports two:

- `address`: AddressSanitizer, for reads and writes outside an allocation,
  use after free and leaks of C memory;
- `undefined`: UndefinedBehaviorSanitizer, for the undefined behavior C
  code, like a package's own C files, can have.

The value named neither, or listed several in one flag. The command line is
checked before anything is compiled, so this is a usage error: `wid` exits
with status 2, and the error points into the command line.

## Example

`main.wid`:

```wid
def main
  puts "hi"
end
```

Running `wid build main.wid -file -sanitize:adress` in its directory:

```text
error[E0710]: unknown sanitizer `adress`
 --> command line:1:36
  |
1 | wid build main.wid -file -sanitize:adress
  |                                    ^^^^^^ not a sanitizer Wid supports
  = note: Wid supports `address` (AddressSanitizer) and `undefined` (UndefinedBehaviorSanitizer)
help: a similar sanitizer exists: `address`
  | wid build main.wid -file -sanitize:address
  = see `wid explain E0710`

run `wid help build` for usage
```

`-sanitize:address,undefined`, the way the C compiler's `-fsanitize=` takes
a list, is the same error, with a fix that gives each sanitizer its own flag:
`-sanitize:address -sanitize:undefined`.

## How to fix

- Name `address` or `undefined`, and repeat the flag to turn on both.
- A sanitizer needs its runtime library, which comes with clang and with
  gcc on Linux; without it, the C compiler's error says so (E0702).

Running `wid build main.wid -file -sanitize:address` builds the program
with AddressSanitizer.
