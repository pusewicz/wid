# E0328: unknown or misused attribute

An attribute written with `@[…]` is not one Wid knows, or it is used the wrong
way. Attributes change how a declaration is compiled, so a misspelled one
would otherwise be silently ignored.

On a method, Wid knows `c`, `export`, `extern`, `no_bounds_check` and `test`.
On a statement, it knows `no_bounds_check`. Structs, enums, unions, constants,
fields and other declarations take no attributes. The same code reports an
attribute written twice, `@[export]` or `@[extern]` given something other than
one string, arguments to an attribute that takes none, `@[extern]` combined
with an attribute that needs a Wid body, and an `@[extern]` method that has a
body.

## Example

```wid
@[expotr("on_tick")]
def on_tick
  puts "tick"
end

def main
  on_tick
end
```

```text
error[E0328]: unknown attribute `@[expotr]`
 --> main.wid:1:3
  |
1 | @[expotr("on_tick")]
  |   ^^^^^^ not an attribute Wid knows
  = note: method attributes: c, export, extern, no_bounds_check, test
help: did you mean `export`?
  | @[export("on_tick")]
  = see `wid explain E0328`
```

## How to fix

- Fix the spelling. `export` gives the function a stable C symbol, `c` gives
  it the C calling convention, and `extern` declares a function implemented
  in C.
- `@[export]` and `@[extern]` take an optional string: the C symbol name, like
  `@[export("on_tick")]`.
- An `@[extern]` method has no body: write `def name(…) -> R` and `end` with
  nothing between them. Its code lives in a C file in the package or in a
  library.
- Put `@[no_bounds_check]` on the statement that should skip bounds checks.

```wid
@[export("on_tick"), c]
def on_tick
  puts "tick"
end

def main
  on_tick
end
```
