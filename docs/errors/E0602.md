# E0602: symbol to document or query not found

<!-- command: doc . Bal -->
<!-- fix-command: doc . Ball -->

`wid doc` documents one symbol when it is given a symbol path after the
package: a name the package declares (`Ball`), a type and one of its members
(`Ball.update`), or an import name first (`rl.draw_circle_v`, for a package
that imports raylib `as: :rl`). The first name is looked up among the
package's own declarations (with those a `cimport` without `as:` adds), its
files' import names, the prelude and the builtin types. This error says no
declaration has that name, or that the path is malformed (`Ball.`).

When a type of the package has a member with the name, the fix names the
type first. When the only argument was read as a symbol of the package in
`.` (see E0601), a note says so.

`wid query def` and `wid query methods` read their symbol path the same
way and report the same error, as JSON on stderr. They see private
declarations too, and when several types have a member with the name
(`wid query def pos`), they offer one fix for each: `Ball.pos`,
`Entity.pos`.

## Example

`main.wid`:

```wid
# A bouncing ball.
struct Ball
  pos: [2]F32

  # Moves the ball by its velocity.
  def update(dt: F32)
  end
end
```

Running `wid doc . Bal` in its directory:

```text
error[E0602]: no symbol `Bal` in this package
 --> command line:1:11
  |
1 | wid doc . Bal
  |           ^^^ not declared in this package
help: a similar name exists: `Ball`
  | wid doc . Ball
  = see `wid explain E0602`
```

## How to fix

- Fix the name; the help suggests a similar one.
- Name a member through its type: `Ball.update`, not `update`.
- Name a symbol of an imported package through the import name the package
  uses for it: `rl.draw_circle_v`.
- Run `wid doc` with the package alone to list what it declares.

Running `wid doc . Ball` shows the struct.
