# E0913: declaration a macro can't generate

A macro called among declarations (at package level, or in a `struct`,
`enum`, `module` or `extend` body) generates declarations that take the
call's place: methods, constants, types, `include`s, `overload` sets and
more macro calls. Two kinds of declaration can't come from a macro:

- **A field of the struct whose body holds the call.** A struct's fields,
  and so its layout, are fixed before the macros in its body run. That is
  what lets a macro read `Self.fields` and generate methods from them. A
  macro that generates a whole `struct` can give it any fields.
- **An `import` or a `cimport`.** Packages are loaded and C headers imported
  before any macro runs, so one in generated code would come too late.

The error points at the declaration in the macro's `quote` and at the call
that generated it. Uses of a rejected field (`player.kills`, `@kills`,
`Player.new(kills: 1)`) aren't reported as missing too, since this error
explains them. An enum's members can't come from a macro either, for the
same reason as a struct's fields: a name alone on a generated line is read as
a macro call (E0201).

## Example

The macro adds a counter field to the struct it is called in:

```wid
macro def counter(name: Symbol) -> Code
  quote do
    #{name}: Int = 0
  end
end

struct Player
  hp: Int = 100
  counter :kills
end

def main
  player = Player.new
  player.kills += 1
  p player
end
```

```text
error[E0913]: a macro can't add fields to `Player`
 --> main.wid:9:12
  |
9 |   counter :kills
  |            ^^^^^ `counter` generates this field
 ::: main.wid:3:5
  |
3 |     #{name}: Int = 0
  |     ------- `kills` is spliced here by `counter`
 ::: main.wid:9:3
  |
9 |   counter :kills
  |   -------------- `counter` expands here
  = note: a struct's layout is fixed before the macros in its body run, which is what lets them read `Self.fields`
help: declare `kills` in `Player` itself, and let the macro generate the methods that use it
  = see `wid explain E0913`
```

## How to fix

Declare the field in the struct, and let the macro generate what works with
it:

```wid
macro def counter(name: Symbol) -> Code
  bump = "bump_#{name.to_s}".to_sym
  quote do
    def #{bump}
      @#{name} += 1
    end
  end
end

struct Player
  hp: Int = 100
  kills: Int = 0
  counter :kills
end

def main
  player = Player.new
  player.bump_kills
  p player
end
```

## A generated `import`

The macro imports the package its generated method uses:

```wid
macro def hex_printer -> Code
  quote do
    import "core:fmt"

    def print_hex(x: Int)
      puts fmt.int(x, base: 16)
    end
  end
end

hex_printer

def main
  print_hex(255)
end
```

```text
error[E0913]: a macro can't generate an `import`
  --> main.wid:3:5
   |
 3 |     import "core:fmt"
   |     ^^^^^^^^^^^^^^^^^ an `import` in generated code
  ::: main.wid:11:1
   |
11 | hex_printer
   | ----------- `hex_printer` expands here
   = note: packages are loaded and C headers imported before any macro runs
help: write it in the file that defines the macro: names in the `quote`'s own code resolve with that file's imports, so the generated code can use the package without importing it
   = see `wid explain E0913`
```

Names in the `quote`'s own code resolve where the macro is defined, with that
file's imports, so import the package there. The code works wherever the
macro is called, even in a file that doesn't import `core:fmt`:

```wid
import "core:fmt"

macro def hex_printer -> Code
  quote do
    def print_hex(x: Int)
      puts fmt.int(x, base: 16)
    end
  end
end

hex_printer

def main
  print_hex(255)
end
```
