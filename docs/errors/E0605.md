# E0605: position to query not found

<!-- command: query type main.wid:5:1 -->
<!-- fix-command: query type main.wid:4:8 -->

`wid query type` takes a position, `file:line:column`, and says what is
there: the innermost expression, name, binding, parameter or written type,
or the name in a declaration, with its type. Lines and columns count from
1, as in diagnostics, and the file is named the way diagnostics show it,
relative to the current directory. This error says there is nothing to
answer for at the position.

The checker records what it checks: blank space, comments and keywords
have no type, and neither has code it never reaches, like a generic method
that nothing instantiates or a field default that no `T.new` uses. The
error then points at the code nearest to the position and suggests asking
about the nearest.

The same error reports a position that isn't `file:line:column` (with a
fix that asks for `def` when it reads as a symbol path), a file the
program doesn't hold (with a similar file, when there is one), and a line
or a column past the end. Like every `wid query` error, it is JSON on
stderr, and stdout holds the document with empty `results`.

## Example

`main.wid`:

```wid
# A bouncing ball.
struct Ball
  # Pixels per second.
  vel: F32

  def speed -> F32 = @vel * 2.0
end
```

## How to fix

- Point at code: a name, an expression or a type. The fix suggests the
  nearest one, and the labels show what is close.
- Count lines and columns from 1, and columns in characters, as
  diagnostics do.
- Name the file as diagnostics show it, and the package that holds it with
  `-in:` when it isn't the package in its directory.

Running `wid query type main.wid:4:8` says that `F32` is a type.
