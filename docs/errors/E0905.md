# E0905: compile-time value can't be used at run time

A `comptime` expression produced a value that can't be stored in the program.
Compile-time values are copied into the program: numbers, strings, enums,
structs, fixed arrays, tuples, optionals, unions and procs that name Wid
methods cross as they are, and a slice crosses as a copy of its elements.
Pointers, dynamic arrays, maps, allocators and `Type` values point at memory
that only exists while the compiler runs, so they can't. That includes the
`^TypeInfo` of `comptime type_info(T)`: call `type_info` in run-time code, or
keep what you read from it, like `comptime type_info(T).size`.

The note names the part of the value that can't cross when it is nested, like
`value.next` for a field.

## Example

The method returns a dynamic array, whose storage belongs to the compiler:

```wid
def squares -> [dynamic]Int
  out = [dynamic]Int.new
  for i in 0...4
    out << i * i
  end
  out
end

SQUARES = comptime squares

def main
  p SQUARES
end
```

```text
error[E0905]: this `[dynamic]Int` can't be used at run time: it holds a dynamic array, whose storage belongs to a compile-time allocator
 --> main.wid:9:11
  |
9 | SQUARES = comptime squares
  |           ^^^^^^^^^^^^^^^^ computed while compiling
  = note: values made at compile time are copied into the program; memory the compiler used is not
help: return a fixed array (`[N]T`) or a slice (`[]T`) of the elements instead
  = see `wid explain E0905`
```

## How to fix

Return a fixed array, or a slice, which crosses as a copy of its elements:

```wid
def squares -> []Int
  out = [dynamic]Int.new
  for i in 0...4
    out << i * i
  end
  out
end

SQUARES = comptime squares

def main
  p SQUARES
end
```
