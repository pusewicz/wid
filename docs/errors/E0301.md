# E0301: mismatched types

A value has a different type from the one a declaration, parameter, field or
return type expects. Wid never converts between types implicitly. That
includes numbers: an `Int` is not accepted where an `F32` is expected, even if
the value would fit. Number literals are the exception: `x: F32 = 10` is fine,
because an untyped literal takes the expected type.

The same code covers related type errors, each with its own message: `nil`
where the type is not optional, a call that returns nothing used as a value,
`main` with parameters or a return type, `for` over something that is not a
range or collection, and `T??`.

## Example

```wid
def half(x: F32) -> F32
  x / 2.0
end

def main
  n = 10
  puts half(n)
end
```

```text
error[E0301]: expected `F32`, found `Int`
 --> main.wid:7:13
  |
7 |   puts half(n)
  |             ^ this has type `Int`
  = note: Wid never converts between numeric types implicitly
help: convert it explicitly with `.to(F32)`
  |   puts half(n.to(F32))
  = see `wid explain E0301`
```

## How to fix

- Convert numbers explicitly: `n.to(F32)`. `to_i` and `to_f` convert to `Int`
  and `F64`, and `to_s` gives a `String`.
- Or give the variable the right type from the start: `n: F32 = 10`.
- For a value that can be missing, use an optional type: `x: Int? = nil`.
- `main` takes no parameters and has no return type: `def main`.
- To loop a number of times, iterate over a range: `for i in 0...n`.
- A type is optional at most once: write `Int?`, not `Int??`.

```wid
def half(x: F32) -> F32
  x / 2.0
end

def main
  n = 10
  puts half(n.to(F32))
end
```
