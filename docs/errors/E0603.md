# E0603: no member with that name to document

<!-- command: doc . Ball.vell -->
<!-- fix-command: doc . Ball.vel -->

In a symbol path such as `Ball.update`, each name after a type is a member of
that type: a field (also one promoted by `using`), an enum member, or a
method, type-level constant or overload set, including the methods of
included modules, extensions and `using` fields. This error says the type has
no member with that name, or that the path goes on after something that has
no members, like a constant or a method (`MAX.x`).

For a builtin type such as `String`, `wid doc` lists the methods that
extensions in the program add to it; its builtin methods (`size`, `to_s`, …)
are described in SPEC.md.

## Example

`main.wid`:

```wid
# A bouncing ball.
struct Ball
  pos: [2]F32
  # Pixels per second.
  vel: [2]F32
end
```

Running `wid doc . Ball.vell` in its directory:

```text
error[E0603]: struct `Ball` has no member `vell`
 --> command line:1:16
  |
1 | wid doc . Ball.vell
  |                ^^^^ not a field, member or method of struct `Ball`
 ::: main.wid:2:8
  |
2 | struct Ball
  |        ---- struct `Ball` is declared here
help: a similar member exists: `vel`
  | wid doc . Ball.vel
  = see `wid explain E0603`
```

## How to fix

- Fix the member's name; the help suggests a similar one, or a note lists
  the members.
- Run `wid doc` on the type alone (`wid doc . Ball`) to see every field,
  member and method, with where each comes from.
- Remove what follows a constant, a method or a field: only types have
  members.

Running `wid doc . Ball.vel` shows the field.
