# E0311: constant does not fit in type

A constant value is outside the range of the type it is stored in. Wid checks
this at compile time, so a constant never silently wraps or truncates. This
covers literals and constant arithmetic (`d: I8 = 100 + 100`), negative values
for unsigned types, integer literals too large for `Int` when no other type is
expected, and enum values that overflow the enum's backing type.

A constant shift that doesn't fit is reported with its value as a power of
two (`1 << 200` is 2^200), whatever the shift amount, and the help names the
largest shift that fits. Untyped arithmetic may go past every integer type on
the way, so `(1 << 100) >> 90` is fine.

Constant arithmetic is exact in 128 bits. An operation whose value goes past
them, like `2 ** 200` or `-(-2^127)`, is reported where it happens, since no
integer type holds it. For a float (`x: F64 = 2 ** 200`) the value is
computed in floating point instead.

## Example

```wid
def main
  small: U8 = 300
  puts small
end
```

```text
error[E0311]: `300` does not fit in `U8`
 --> main.wid:2:15
  |
2 |   small: U8 = 300
  |               ^^^ `U8` holds values from 0 to 255
help: use a wider type like `U16`, or a value in range
  = see `wid explain E0311`
```

## How to fix

- Use a type wide enough for the value: `U16`, `I32`, `Int`.
- For negative values, use a signed type such as `I8` or `Int`.
- For an enum, widen its backing type: `enum Tile : U16 … end`.
- A literal above `Int`'s maximum fits in `U64`: `x: U64 = 9223372036854775808`.
- Shift by fewer bits: `Int` holds up to `1 << 62`, `U64` up to `1 << 63`.
- For a value past every integer type, use a float: `x: F64 = 2 ** 200`.
- Ranges: `U8` 0 to 255, `I8` -128 to 127, `U16` 0 to 65535, `I16` -32768 to
  32767.

```wid
def main
  small: U16 = 300
  puts small
end
```
