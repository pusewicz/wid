# E0402: `guard` else-branch does not exit

The `else` branch of a `guard` can reach its `end`. After a `guard`, the code
uses the bound names as if the value was present. If the failure path fell
through into that code, those names would have no value. So the branch must
end with `return`, `break`, `next` or `panic`. The same applies to the `Bool`
form, `guard cond else … end`.

## Example

```wid
def checked_div(a: Int, b: Int) -> (Int, Error)
  return {}, :division_by_zero if b == 0
  return a / b, nil
end

def main
  guard q = checked_div(10, 0) else |err|
    p err
  end
  puts q
end
```

```text
error[E0402]: the `else` of a `guard` must leave the scope
 --> main.wid:7:3
  |
7 |   guard q = checked_div(10, 0) else |err|
  |   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ control can continue past this guard without a value
  = note: end the else-branch with `return`, `break`, `next` or `panic`
help: for example, end it with `return`
  = see `wid explain E0402`
```

The suggested `return` fits the method's return type, such as `return nil`
for `T?` or `return {}, :some_error` for `(T, Error)`.

## How to fix

- End the branch with `return`. In a method with a return type, return a
  value, like `return {}, err` in a fallible function.
- Inside a loop, `next` skips to the next iteration and `break` leaves the
  loop.
- For a failure that means a bug, `panic` stops the program.
- To continue with a default instead, don't use `guard`. For an optional, use
  `maybe || default`.

```wid
def checked_div(a: Int, b: Int) -> (Int, Error)
  return {}, :division_by_zero if b == 0
  return a / b, nil
end

def main
  guard q = checked_div(10, 0) else |err|
    p err
    return
  end
  puts q
end
```
