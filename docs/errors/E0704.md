# E0704: two C declarations get the same Wid name

`cimport` turns C names into Wid names with fixed rules: `strip_prefix:`
first, then `snake_case` for functions, `PascalCase` for types, and the
C spelling for constants. Sometimes two declarations end up with the same
name, like `m_log` and `m_Log`. Neither gets it, so a use can't silently call
the wrong one, and using the name reports this error.

## Example

`mathlib.h`:

```c
double m_log(double x);
void m_Log(const char *message);
```

`main.wid`:

```wid
cimport "mathlib.h", as: :m, strip_prefix: "m_"

def main
  m.log(2.0)
end
```

```text
error[E0704]: `log` is ambiguous: `m_Log` and `m_log` both become `log` in Wid
 --> main.wid:4:5
  |
4 |   m.log(2.0)
  |     ^^^ cimport left both out
  = note: cimport turns C names into Wid names with fixed rules, and these end up the same
help: give the others their own names, so `log` means `m_Log`
  | cimport "mathlib.h", as: :m, strip_prefix: "m_", names: {m_log: :log_2}
  = see `wid explain E0704`
```

## How to fix

Give one of them its own Wid name with `names:`:

```wid
cimport "mathlib.h", as: :m, strip_prefix: "m_", names: {m_Log: :log_message}

def main
  m.log(2.0)
  m.log_message("done")
end
```
