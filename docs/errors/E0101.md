# E0101: unexpected character

The source contains a character that is not part of Wid's syntax. The lexer
reports it and skips it, so later errors on the same line are often side
effects of this one. Common causes are a `$` or `@` with no name after it, a
backtick (Wid has no backtick strings or shell commands), and a `\` that is
not at the end of a line.

## Example

```wid
def main
  price = $5
  puts price
end
```

```text
error[E0101]: unexpected character `$`
 --> main.wid:2:11
  |
2 |   price = $5
  |           ^ `$` must be followed by a type parameter name like `$T`
help: remove it
  |   price = 5
  = see `wid explain E0101`
```

Each backtick in `` `ready` `` is reported separately, and the name between
them is then reported as undefined (E0201). Fixing the backticks fixes all
three.

## How to fix

- Delete the character, or replace it with the construct you meant. Strings
  use `"…"` or `'…'`.
- `$` must start a type parameter name, like `$T`.
- `@` must be followed by a field name (`@pos`) or by `[` for attributes
  (`@[c]`).
- `\` is only valid inside strings and at the very end of a line, where it
  continues the statement.

```wid
def main
  price = 5
  puts price
end
```
