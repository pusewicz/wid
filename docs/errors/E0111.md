# E0111: misplaced splice

Outside a string literal, `#{` always starts a splice. A splice inserts a
value into the code that a `macro def` builds with `quote do … end`, so it
only means something inside a `quote`, and there only as a whole value or
name. This code covers a splice in the wrong place: outside a `quote`,
inside another splice, or glued to text in a name.

Most of the time a splice outside a `quote` was meant to be a comment: in
Wid a comment is `#` followed by a space, and `#{TODO}` is not one. When the
`#{` starts a line or follows a complete expression, the compiler reads the
rest of the line as that comment and the fix adds the space. When the splice
stands where a value or name is expected, as in `x = #{y}`, the fix removes
the `#{` and `}` instead. A splice glued to a name, as in `def bump_#{name}`,
is never a comment (see the last two sections).

A splice inside another splice's expression, like `#{name(#{arg})}`, is
misplaced too. The expression inside `#{…}` already runs in the macro, so it
uses the macro's values directly: write `#{name(arg)}`. There a name glued
to a splice, like `#{foo_#{name}}`, is a name built from a string, which
macro code writes `"foo_#{name}".to_sym`; the fix builds it before the
`quote` and splices it, `#{foo_name}`.

## Example

```wid
def main
  total = 0
  #{TODO} add the bonus round
  for x in [1, 2, 3]
    total += x
  end
  puts total
end
```

```text
error[E0111]: `#{` starts a splice outside a `quote`
 --> main.wid:3:3
  |
3 |   #{TODO} add the bonus round
  |   ^^^^^^^ a splice only works inside `quote do … end`
  = note: outside a string, `#{` always starts a splice; a comment starts with `# `
help: if this is a comment, add a space after `#`
  |   # {TODO} add the bonus round
  = see `wid explain E0111`
```

## How to fix

- Start comments with `# `, a hash and a space.
- To insert values into generated code, write the splice inside a `quote`
  in a `macro def`, and return the `quote` from the macro.
- Inside a splice, use the macro's values without another `#{…}`.

```wid
def main
  total = 0
  # TODO: add the bonus round
  for x in [1, 2, 3]
    total += x
  end
  puts total
end
```

## A splice glued to a name

```wid
struct Hero
  hp: Int
end

macro def bumper(name: Symbol) -> Code
  quote do
    def bump_#{name} -> Int = @#{name} + 1
  end
end

extend Hero
  bumper :hp
end

def main
  hero = Hero.new(hp: 10)
  p hero.bump_hp
end
```

```text
error[E0111]: a splice can't be part of a name
 --> main.wid:7:9
  |
7 |     def bump_#{name} -> Int = @#{name} + 1
  |         ^^^^^^^^^^^^ a splice inserts a whole name, not part of one
  = note: the text next to the splice is read as a separate name
help: build the name as a `Symbol` in the macro, before the `quote`, and splice it whole
  |   bump_name = "bump_#{name}".to_sym
  |   quote do
  |     def #{bump_name} -> Int = @#{name} + 1
  = see `wid explain E0111`
```

In Ruby, `define_method("bump_#{name}")` builds a method name from a
string. In a `quote`, a splice inserts a whole name, so text written next
to it is read as a separate name and can't join the one it inserts. (The
rest of the check reads it as the name it was meant to build, so
`hero.bump_hp` adds no error of its own.) Build the name in the macro, as
a `Symbol` made with `to_sym`, and splice it whole; the fix does that, to
review:

```wid
struct Hero
  hp: Int
end

macro def bumper(name: Symbol) -> Code
  bump_name = "bump_#{name}".to_sym
  quote do
    def #{bump_name} -> Int = @#{name} + 1
  end
end

extend Hero
  bumper :hp
end

def main
  hero = Hero.new(hp: 10)
  p hero.bump_hp
end
```

## A glued splice outside a `quote`

```wid
def bump_#{name} -> Int = 1

def main
end
```

```text
error[E0111]: `#{` starts a splice outside a `quote`
 --> main.wid:1:5
  |
1 | def bump_#{name} -> Int = 1
  |     ^^^^^^^^^^^^ a splice only works inside `quote do … end`
  = note: inside one, a splice can't be part of a name either: it inserts a whole name
help: build the name as a `Symbol` in the macro, before the `quote`, and splice it whole: `bump_name = "bump_#{name}".to_sym`, then `#{bump_name}`
  = see `wid explain E0111`
```

Outside a `quote` nothing is spliced, and a splice glued to a name is never
read as a comment. It is reported once, and the rest of the line is read as
the declaration it was written in, here a method named `bump_#{name}` that
no code can call, so `def main` is still found. To generate methods with
names like this, write them in a `quote` in a `macro def` and build each
name whole, as in the section above.
