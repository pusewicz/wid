# E0111: splice outside `quote`

Outside a string literal, `#{` always starts a splice. A splice inserts a
value into the code that a `macro def` builds with `quote do … end`, so it
only means something inside a `quote`. Anywhere else it is an error.

Most of the time the splice was meant to be a comment: in Wid a comment is
`#` followed by a space, and `#{TODO}` is not one. When the `#{` starts a
line or follows a complete expression, the compiler reads the rest of the
line as that comment and the fix adds the space. When the splice stands
where a value or name is expected, as in `x = #{y}`, the fix removes the
`#{` and `}` instead.

The same code is used for a splice inside another splice's expression, like
`#{name(#{arg})}`. The expression inside `#{…}` already runs in the macro, so
it uses the macro's values directly: write `#{name(arg)}`. It is also used
for a splice glued to text in a name, like `def bump_#{name}` (see the last
section).

## Example

```wid
def main
  total = 0
  #{TODO} add the bonus round
  for x in [1, 2, 3]
    total += x
  end
  puts total
end
```

```text
error[E0111]: `#{` starts a splice outside a `quote`
 --> main.wid:3:3
  |
3 |   #{TODO} add the bonus round
  |   ^^^^^^^ a splice only works inside `quote do … end`
  = note: outside a string, `#{` always starts a splice; a comment starts with `# `
help: if this is a comment, add a space after `#`
  |   # {TODO} add the bonus round
  = see `wid explain E0111`
```

## How to fix

- Start comments with `# `, a hash and a space.
- To insert values into generated code, write the splice inside a `quote`
  in a `macro def`, and return the `quote` from the macro.
- Inside a splice, use the macro's values without another `#{…}`.

```wid
def main
  total = 0
  # TODO: add the bonus round
  for x in [1, 2, 3]
    total += x
  end
  puts total
end
```

## A splice glued to a name

```wid
struct Hero
  hp: Int
end

macro def bumper(name: Symbol) -> Code
  quote do
    def bump_#{name} -> Int = @#{name} + 1
  end
end

extend Hero
  bumper :hp
end

def main
  hero = Hero.new(hp: 10)
  p hero.bump_hp
end
```

```text
error[E0111]: a splice can't be part of a name
 --> main.wid:7:9
  |
7 |     def bump_#{name} -> Int = @#{name} + 1
  |         ^^^^^^^^^^^^ a splice inserts a whole name, not part of one
  = note: the text next to the splice is read as a separate name
help: build the name as a `Symbol` in the macro, before the `quote`, and splice it whole
  |   bump_name = "bump_#{name}".to_sym
  |   quote do
  |     def #{bump_name} -> Int = @#{name} + 1
  = see `wid explain E0111`
```

In Ruby, `define_method("bump_#{name}")` builds a method name from a
string. In a `quote`, a splice inserts a whole name, so text written next
to it is read as a separate name and can't join the one it inserts. (The
rest of the check reads it as the name it was meant to build, so
`hero.bump_hp` adds no error of its own.) Build the name in the macro, as
a `Symbol` made with `to_sym`, and splice it whole; the fix does that, to
review:

```wid
struct Hero
  hp: Int
end

macro def bumper(name: Symbol) -> Code
  bump_name = "bump_#{name}".to_sym
  quote do
    def #{bump_name} -> Int = @#{name} + 1
  end
end

extend Hero
  bumper :hp
end

def main
  hero = Hero.new(hp: 10)
  p hero.bump_hp
end
```
