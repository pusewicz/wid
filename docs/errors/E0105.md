# E0105: unexpected token

The parser found a token where the grammar does not allow it. The message says
what it expected and what it found. Many E0105 messages are more specific: a
parameter or block parameter without a type, a type parameter written as a
parameter of its own (`$T, xs: []T`), a value parameter in a method's array
type (`xs: [$N]Int`), `^` used as xor, a non-empty
`{…}` literal, Ruby's `::` (`Pool::CAP`), an uppercase enum member, a `case` with no `when`, a stray
`end`, a declaration nested inside a method, a `macro def` inside a type,
a field written with a space before its `:` (`pos :Vec2`), an `import` or `cimport` inside
a `struct`, `enum`, `module` or `extend` body, a field in a module or enum, a
`private` field, enum member or statement, `private` before a line that
declares no name (an `import`, `include`, `extend` or `comptime if`), a
list of values used as a statement, a `guard` without `else`, an empty
splice `#{}` in a `quote` or one where a symbol or a path is expected
(`overload #{name}`, `import #{path}`), a type's `?` written after a space
(`size_of(Int ?)`, which reads as an unfinished `cond ? a : b`), or a `(`,
`[`, `{` or `|` left open at the end of its line, or a line that ends with
an operator, when the next line doesn't continue it. An operator with
nothing after it before a `)`, `]` or `}` (`[1, 2 +]`) is one error that
names the operator, and the bracket still closes.

## Example

```wid
def double(x) -> Int
  x * 2
end

def main
  puts double(4)
end
```

```text
error[E0105]: parameter `x` needs a type
 --> main.wid:1:12
  |
1 | def double(x) -> Int
  |            ^ every parameter has a declared type
help: add its type (`Int` is only an example)
  | def double(x: Int) -> Int
  = see `wid explain E0105`
```

The suggested `Int` is a placeholder. Use the type the method really takes.

## How to fix

- Give every parameter a type.
- Introduce a type parameter inside the type of the parameter it is inferred
  from: `def first(xs: []$T) -> T`, not `def first($T, xs: []T)` or Odin's
  `$T: typeid`.
- A method can't take a value parameter like the `$N` of `xs: [$N]Int`; only
  generic structs do (`struct Pool($T, $N: Int)`). Take a slice,
  `xs: []Int`, which an array argument converts to, and read its length with
  `xs.size`.
- Bitwise xor is `~`. `^` only builds pointer types (`^T`) and dereferences
  (`p^`).
- A type's constants and methods are reached with `.`: `Pool.CAP`, not
  Ruby's `Pool::CAP`.
- `{}` is only the zero value. Build a struct with `Type.new(field: value)`.
- Write `import` and `cimport` at the top level of the file, next to its
  other imports; their names are visible in every declaration of the file.
- Enum members are lowercase: `north`, not `North`.
- A field's `:` touches its name: `pos: Vec2`, not `pos :Vec2`.
- Fields and enum members are always public, so remove `private` from
  them. `private` applies to methods and other named declarations: not to
  an `import`, `include`, `extend`, `comptime if` or a statement.
- An optional type's `?` touches the type: `Int?`. With a space before it,
  `?` starts a conditional, `cond ? a : b`.
- Close a `(`, `[` or `{` on the line that opens it, or end the line with
  `,` or an operator to go on to the next one: a declaration or an `end`
  never continues a line.
- A `quote`'s code goes in `do … end`, not in braces, and a macro is
  declared with `macro def`, at the top level of a file: macros are package
  members, not members of a type. Calls of one written inside a type
  (`x.name`) aren't reported again.
- A `guard`'s `else` branch starts on the line after `else` and ends with
  `end`, like every block.
- In a `quote`, a splice inserts a name; where a symbol is expected, splice
  a symbol literal: `overload :#{name}, :a, :b`. Generated code can't
  `import`, so write imports in the macro's file.
- Give an operator its right-hand value, or remove it: `[1, 2 + 3]` or
  `[1, 2]`, not `[1, 2 +]`.
- Give a named argument its value: `g(a: 1, b: 2)`, not `g(a: , b: 2)`. The
  arguments after one without a value are still checked.
- Read the "expected …" part of the message. It names the token that would make
  the line valid, often a missing `)`, `,`, `=` or `end`.

```wid
def double(x: Int) -> Int
  x * 2
end

def main
  puts double(4)
end
```

## A `private` field

```wid
struct Hero
  private hp: Int
  name: String
end

def main
  hero = Hero.new(hp: 100, name: "Ayla")
  hero.hp -= 10
  puts hero.hp
end
```

```text
error[E0105]: a field can't be `private`
 --> main.wid:2:3
  |
2 |   private hp: Int
  |   ^^^^^^^ fields are always public
  = note: any code can read and write `hp` directly; `private` applies to methods and other declarations
help: remove `private`
  |   hp: Int
  = see `wid explain E0105`
```

As in Odin, a struct's fields are always public: code reads and writes them
directly, like `hero.hp` or `@hp` in a method, and there are no getter or
setter methods. `private` hides methods (from code outside their type) and
other declarations (from other packages), so remove it from the field:

```wid
struct Hero
  hp: Int
  name: String
end

def main
  hero = Hero.new(hp: 100, name: "Ayla")
  hero.hp -= 10
  puts hero.hp
end
```

## `private` where it hides nothing

```wid
module Greet
  def hi -> String = "hi"
end

struct Hero
  private include Greet
  hp: Int
end

def main
  private hero = Hero.new(hp: 10)
  puts hero.hi
end
```

```text
error[E0105]: an `include` can't be `private`
 --> main.wid:6:3
  |
6 |   private include Greet
  |   ^^^^^^^ `private` has nothing to hide here
  = note: `include` mixes a module's methods into this type; the ones the module declares with `private def` stay private
help: remove `private`
  |   include Greet
  = see `wid explain E0105`

error[E0105]: `private` applies only to declarations
  --> main.wid:11:3
   |
11 |   private hero = Hero.new(hp: 10)
   |   ^^^^^^^ this line is a statement
   = note: `private` hides a method outside its type, or a type, constant or macro outside its package; a local variable is visible only in its method anyway
help: remove `private`
   |   hero = Hero.new(hp: 10)
   = see `wid explain E0105`
```

`private` hides a declaration by its name: a method from code outside its
type, and a type, constant or macro from other packages. An `include` names
nothing of its own (the methods it mixes in keep the `private` they were
declared with), and a local variable is only ever visible in its method.
The same goes for an `import`, an `extend` and a `comptime if`, and for enum
members, which are always public. Remove `private`:

```wid
module Greet
  def hi -> String = "hi"
end

struct Hero
  include Greet
  hp: Int
end

def main
  hero = Hero.new(hp: 10)
  puts hero.hi
end
```

## A list left open before a declaration

```wid
PRIMES = [2, 3, 5
def main
  p PRIMES
end
```

```text
error[E0105]: expected `]` to close the array, found end of line
 --> main.wid:1:18
  |
1 | PRIMES = [2, 3, 5
  |                  ^ expected `]`
  |          - this `[` is never closed
help: close it
  | PRIMES = [2, 3, 5]
  = see `wid explain E0105`
```

Once an element is complete, a line end may only lead to a `,` or the
closing `]`. The next line here starts a declaration, so the array was left
open at the end of its line: that is the one error, and `def main` is
parsed on its own. The same goes for a call's argument list, an index, a
parenthesized expression, a `{ }` block, a method's parameter list (the
method ends with that line when a declaration follows it), and a type's
arguments, array length or map key (`Pool(Int, 4`, `[4`, `map[String`).
A line that ends with an operator, `=` or `,` before a declaration is
missing the rest of its expression, and so is a named argument (`add(a:`)
before a line indented no deeper than the call's. A line indented under
the list that starts a value is read as the next element, with its `,`
missing. Close the list:

```wid
PRIMES = [2, 3, 5]
def main
  p PRIMES
end
```

## A field with a space before its `:`

```wid
struct Vec2
  x: F32
end

struct Ball
  pos :Vec2
end

def main
  p Ball.new.pos.x
end
```

```text
error[E0105]: a field's `:` goes right after its name
 --> main.wid:6:6
  |
6 |   pos :Vec2
  |      ^^ this reads as a call of a macro `pos` with the symbol `:Vec2`
  = note: no macro `pos` is in scope, and `Vec2` is a type, so this is the field `pos: Vec2` with its space before the `:`
help: write the `:` right after the field's name
  |   pos: Vec2
  = see `wid explain E0105`
```

A field is declared as `name: Type`, with the `:` touching the name. With
the space before the `:` instead, `:Vec2` is a symbol, and a name followed
by an argument among declarations is a macro call, which would generate
declarations in the struct. No macro `pos` exists and `Vec2` is a type, so
the line is the field `pos`: that is the one error, and uses of `pos` aren't
reported again. Move the `:`:

```wid
struct Vec2
  x: F32
end

struct Ball
  pos: Vec2
end

def main
  p Ball.new.pos.x
end
```

## Ruby's `::`

```wid
struct Pool
  CAP = 4
end

def main
  p Pool::CAP
end
```

```text
error[E0105]: Wid writes `.` where Ruby writes `::`
 --> main.wid:6:9
  |
6 |   p Pool::CAP
  |         ^^ Ruby's scope operator
  = note: a type's constants and methods, and a package's members, are reached with `.`, as in `Pool.CAP`
help: write `.`
  |   p Pool.CAP
  = see `wid explain E0105`
```

Ruby reaches a constant inside a class or module with `::`. Wid has one
operator for every member: `.` reaches a type's constants and methods
(`Pool.CAP`, `Vec2.zero`) and a package's members (`geo.Vec2`). The line is
read as if `.` were written, so this is the one error. Write `.`:

```wid
struct Pool
  CAP = 4
end

def main
  p Pool.CAP
end
```
