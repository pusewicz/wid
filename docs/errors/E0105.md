# E0105: unexpected token

The parser found a token where the grammar does not allow it. The message says
what it expected and what it found. Many E0105 messages are more specific: a
parameter or block parameter without a type, `^` used as xor, a non-empty
`{…}` literal, an uppercase enum member, a `case` with no `when`, a stray
`end`, a declaration nested inside a method, a field in a module or enum, a
list of values used as a statement, a `guard` without `else`, an empty
splice `#{}` in a `quote`, or a type's `?` written after a space
(`size_of(Int ?)`, which reads as an unfinished `cond ? a : b`).

## Example

```wid
def double(x) -> Int
  x * 2
end

def main
  puts double(4)
end
```

```text
error[E0105]: parameter `x` needs a type
 --> main.wid:1:12
  |
1 | def double(x) -> Int
  |            ^ every parameter has a declared type
help: add its type (`Int` is only an example)
  | def double(x: Int) -> Int
  = see `wid explain E0105`
```

The suggested `Int` is a placeholder. Use the type the method really takes.

## How to fix

- Give every parameter a type.
- Bitwise xor is `~`. `^` only builds pointer types (`^T`) and dereferences
  (`p^`).
- `{}` is only the zero value. Build a struct with `Type.new(field: value)`.
- Enum members are lowercase: `north`, not `North`.
- An optional type's `?` touches the type: `Int?`. With a space before it,
  `?` starts a conditional, `cond ? a : b`.
- Read the "expected …" part of the message. It names the token that would make
  the line valid, often a missing `)`, `,`, `=` or `end`.

```wid
def double(x: Int) -> Int
  x * 2
end

def main
  puts double(4)
end
```
