# E0210: import cycle

Two or more packages import each other, directly or through other packages.
Wid's package graph has no cycles, so every package can be checked and built
after the packages it depends on. The note lists the packages in the cycle,
and the error points at the import that closes it.

A package that imports itself (`import "."`) gets the same code, with a fix
that removes the import: the files of a package already see each other's
declarations.

## Example

`physics/body.wid`:

```wid
import "../render"

def step(x: F32, dt: F32) -> F32
  render.mark(x)
  x + dt
end
```

`render/draw.wid`:

```wid
import "../physics"

def mark(x: F32)
  puts x
end

def preview(x: F32) -> F32 = physics.step(x, 0.5)
```

`main.wid`:

```wid
import "./physics"

def main
  puts physics.step(1.0, 0.5)
end
```

```text
error[E0210]: packages import each other in a cycle
 --> render/draw.wid:1:8
  |
1 | import "../physics"
  |        ^^^^^^^^^^^^ this import closes the cycle
  = note: cycle: physics -> render -> physics
help: move the shared declarations into a third package that both can import
  = see `wid explain E0210`
```

## How to fix

- Move what both sides need into a third package that imports neither. Here
  `mark` moves to `debug/mark.wid`, and `render` keeps only `preview`.
- If the two packages are really one unit, merge them.
- Or invert one dependency: pass a `proc` callback down instead of importing
  the higher-level package.

`debug/mark.wid`:

```wid
def mark(x: F32)
  puts x
end
```

`physics/body.wid`:

```wid
import "../debug"

def step(x: F32, dt: F32) -> F32
  debug.mark(x)
  x + dt
end
```

`render/draw.wid`:

```wid
import "../physics"

def preview(x: F32) -> F32 = physics.step(x, 0.5)
```
