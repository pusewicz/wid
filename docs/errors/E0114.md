# E0114: enum member does not start with a capital letter

An enum's members are constants of the enum, so they are named like
constants, as in Ruby: in `PascalCase` (`North`, `NotFound`) or
`UPPER_CASE` (`NORTH`, `NOT_FOUND`). Either style works, and the first
letter is always a capital. That keeps `Dir.North` reading like any other
constant reached through a type, such as `Pool.CAP`, and keeps a member
apart from a method: `Dir.North` is a member, `d.opposite` a method.

A member written in lowercase is this error. The members of `Error`, which
a program names where it uses them (`return {}, .NotFound`), follow the
same rule, so `.not_found` where an `Error` is expected is this error too.

The checker keeps a lowercase member under its `PascalCase` name, so code
that already spells it that way isn't reported again; a use written in
lowercase (`.north`) is E0204 with a fix to the member's spelling.

## Example

```wid
enum Dir
  north
  south
end

def find(n: Int) -> (Int, Error)
  return 0, .not_found if n < 0
  return n, nil
end

def main
  d: Dir = .North
  _, err = find(1)
  p d, Dir.South, err
end
```

## How to fix

- Capitalize the member, as the fix does: `north` becomes `North` and
  `not_found` becomes `NotFound`. `NORTH` and `NOT_FOUND` work too.
- Spell its uses the same way: `.North`, `Dir.North`, `when .North`.
- A macro that splices a member's name takes it capitalized, as a symbol
  argument such as `:North`, or builds a capitalized string before
  `.to_sym`; a name that doesn't fit is E0911 at the call.

```wid
enum Dir
  North
  South
end

def find(n: Int) -> (Int, Error)
  return 0, .NotFound if n < 0
  return n, nil
end

def main
  d: Dir = .North
  _, err = find(1)
  p d, Dir.South, err
end
```
