# E0323: expected a value

An expression is used as a value but has none. A method without a return type
returns nothing, so its result cannot be stored or passed on. The same goes
for a proc literal written without `-> R`.

The same code reports other things that are not values:

- a loop (`while`, `until`, `loop`, `for`) used as a value, or ending a
  method or a branch whose value is wanted when it can finish (see below);
- a range on its own, like `r = 1..3`;
- the name of a type, struct, enum or package, like `F32` or `Ball`, or
  `Self` in a method (`"#{Self}"`: its name is `type_info(Self).name`);
- a type written in place, like `[]Int`, `^Node` or `Int?` (a `?` right
  after a type's name makes it optional; a conditional `c ? a : b` has a
  space before its `?`), or a C type of `core:c`, like `C.int` or
  `C.int?`; a type a macro splices where a value goes (`p #{t}` with
  `t: Type`) is named as the type it inserts, like `Int`;
- a type parameter, like `T` in a method of `struct Slot($T)`: where an
  integer is expected the fix writes `size_of(T)`, and `type_info(T)` or a
  `Type` parameter (`t: Type`) give other values about a type;
- `method(:name)` of a method that takes a block or needs a receiver;
- `type_info(Never)`, or `type_info` of code that never finishes, like a call
  to a `-> Never` method: no value has type `Never`, so there is nothing to
  describe;
- `---` as a constant's value (`BUF: [4]U8 = ---`): `---` opts a variable
  out of zeroing, and a constant has no variable to leave uninitialized
  (see below);
- a branch without a value in the `if`, `case` or `comptime if` that ends a
  macro's code, when the call's value is used (`x = say("hi")`): that last
  line gives the call's value. Called as a statement (`say "hi"`), the
  macro's last line is a statement too and needs no value.

## Example

```wid
def greet(name: String)
  puts name
end

def main
  message = greet("Ada")
  puts message
end
```

```text
error[E0323]: this expression has no value
 --> main.wid:6:13
  |
6 |   message = greet("Ada")
  |             ^^^^^^^^^^^^ it returns nothing, so there is nothing to store
  = see `wid explain E0323`
```

## How to fix

- If the method should produce a value, declare its return type:
  `def greet(name: String) -> String`. For a proc, write
  `->(x: Int) -> Int { … }`.
- If it should not, call it as a statement and don't store the result.
- To make a value of a type, don't write the type alone: use `{}` where the
  type is expected (`grid: [4]F32 = {}`), a literal (`nil` for an optional,
  `[1, 2]` for an array, `->(x: Int) -> Int { x * 2 }` for a proc),
  `Vec2.new(…)` for a struct, or `[dynamic]Int.new` and `map[String]Int.new`
  for the containers that have one. Where a `Type` is expected, as in a
  `t: Type` parameter, any type is a value: `name_of([]Int)`.
- To get a result out of a loop, assign it inside the loop to a variable
  declared before the loop.
- Use ranges directly in `for`, `case` and slicing: `for i in 1..3`.
- Pass `type_info` a type that has values, or remove the call.
- Call a macro whose code ends without a value as a statement of its own,
  or make each branch of its last line end with a value.

```wid
def greet(name: String) -> String
  "hello, #{name}"
end

def main
  message = greet("Ada")
  puts message
end
```

## A loop at the end of a method

A method's last line gives its value, and a loop has none. A loop that
never finishes is the exception: `loop do`, `while true` or `until false`
without a `break` that leaves it can end the method, because nothing after
it runs, as after `panic`. A loop that can finish, at a `break`, when its
condition fails or after its last element, leaves the method without a
value.

```wid
def find(n: Int) -> Int
  i = 0
  loop do
    break if i * i >= n
    i += 1
  end
end

def main
  p find(10)
end
```

```text
error[E0323]: loops do not produce a value
 --> main.wid:3:3
  |
3 |   loop do
  |   ^^^^^^^ the last line gives the value, but a loop has none
4 |     break if i * i >= n
  |     ----- `break` leaves the loop here, and the code after it runs
  = note: only a loop that never finishes, like `loop do` without a `break`, may end a method or a branch without a value after it
help: give the value on a line after the loop
  |   end
  |   …
  = see `wid explain E0323`
```

Give the value after the loop, or `return` it from inside the loop and
drop the `break`:

```wid
def find(n: Int) -> Int
  i = 0
  loop do
    return i if i * i >= n
    i += 1
  end
end

def main
  p find(10)
end
```

## `---` as a constant's value

Wid has no package-level variables: a name declared at package level, or
written in capitals in a type, is a constant, and its value is computed while
compiling. `---` gives it none, since it only opts a variable out of zeroing.

```wid
BUF: [4]U8 = ---

def main
  p BUF
end
```

```text
error[E0323]: the constant `BUF` needs a value
 --> main.wid:1:14
  |
1 | BUF: [4]U8 = ---
  |              ^^^ `---` leaves it without one
  = note: Wid has no package-level variables, so `BUF` is a constant: a constant's value is computed while compiling, and `---` only opts a variable out of zeroing
help: give it the value it should hold
  | BUF: [4]U8 = …
help: or make it the zero value
  | BUF: [4]U8 = {}
help: for state that changes, keep it in a struct that methods receive
  = see `wid explain E0323`
```

Give the constant its value, or `{}` for the zero value of its type. For a
buffer that code writes to, declare a variable inside a method
(`buf: [4]U8 = ---`), or keep it in a struct that methods receive.

```wid
BUF: [4]U8 = {}

def main
  p BUF
end
```
