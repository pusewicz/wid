# E0323: expected a value

An expression is used as a value but has none. A method without a return type
returns nothing, so its result cannot be stored or passed on. The same goes
for a proc literal written without `-> R`.

The same code reports other things that are not values:

- a loop (`while`, `until`, `loop`, `for`) used as a value;
- a range on its own, like `r = 1..3`;
- the name of a type, struct, enum or package, like `F32` or `Ball`;
- `method(:name)` of a method that takes a block or needs a receiver;
- `type_info(Never)`, or `type_info` of code that never finishes, like a call
  to a `-> Never` method: no value has type `Never`, so there is nothing to
  describe.

## Example

```wid
def greet(name: String)
  puts name
end

def main
  message = greet("Ada")
  puts message
end
```

```text
error[E0323]: this expression has no value
 --> main.wid:6:13
  |
6 |   message = greet("Ada")
  |             ^^^^^^^^^^^^ it returns nothing, so there is nothing to store
  = see `wid explain E0323`
```

## How to fix

- If the method should produce a value, declare its return type:
  `def greet(name: String) -> String`. For a proc, write
  `->(x: Int) -> Int { … }`.
- If it should not, call it as a statement and don't store the result.
- To make a value of a type, use `Type.new(…)`, not the type name alone.
- To get a result out of a loop, assign it inside the loop to a variable
  declared before the loop.
- Use ranges directly in `for`, `case` and slicing: `for i in 1..3`.
- Pass `type_info` a type that has values, or remove the call.

```wid
def greet(name: String) -> String
  "hello, #{name}"
end

def main
  message = greet("Ada")
  puts message
end
```
