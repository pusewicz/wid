# E0319: block not expected or missing

A block was passed to a method that has no block parameter, or a method that
requires a block was called without one. A method takes a block by declaring
`&blk: block(T) -> R` and runs it with `yield`. Blocks are inlined at the call
site, so they only exist as that parameter.

The same code reports the other block mismatches:

- calling a block method without a block: `` `twice` needs a block ``, with a
  suggested `do |x| … end` to add;
- a block with more parameters than the method yields:
  ``block parameter `b` receives nothing``;
- `block(…)` used as a field, variable or return type;
- a `&` parameter whose type is not `block(…)`;
- a proc literal that declares a `&block` parameter.

## Example

```wid
def total(a: Int, b: Int) -> Int = a + b

def main
  puts total(1, 2) { |x| x * 2 }
end
```

```text
error[E0319]: `total` does not take a block
 --> main.wid:4:20
  |
4 |   puts total(1, 2) { |x| x * 2 }
  |                    ^^^^^^^^^^^^^ this block is never called
help: methods receive blocks by declaring `&blk: block(…)` and calling `yield`
  = see `wid explain E0319`
```

## How to fix

- Remove the block from the call, or give the method a `&blk: block(…)`
  parameter and `yield` to it.
- Pass a block to a method that needs one: `twice { |n| puts n }`, or
  `twice do |n| … end` for several lines.
- Give the block only as many parameters as the method yields.
- For a callback you need to store, use a `proc(…)` type instead of
  `block(…)`: `on_hit: proc(Int)`. Procs cannot take blocks; give them a
  `proc` parameter instead.

```wid
def total(a: Int, b: Int, &blk: block(Int) -> Int) -> Int
  yield(a) + yield(b)
end

def main
  puts total(1, 2) { |x| x * 2 }
end
```
