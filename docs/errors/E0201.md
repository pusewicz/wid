# E0201: undefined name

The code uses a name that nothing in scope declares. In Wid the first
assignment declares a variable, so a misspelled name in a read is not
silently a new variable: it is an error. The message says what kind of name
was expected: a name, variable, method, constant, package or module. A name
an imported package doesn't declare reads "`geo` has no member `Missing`",
with the closest of the package's public names, or a list of them when the
package declares only a few. The same code reports an `overload` set that
lists a method that doesn't exist. When a declared name is close in
spelling, the help offers it. Inside a method of a type, that includes the
methods a call without a receiver reaches: the type's own, those its modules
mix in, those `extend` blocks add and those its `using` fields promote, so
`heall(1)` suggests `heal(1)`. Inside a method, a name that is a field of
`self`, read bare or called like a method (`hp()`), gets the fix to read it
with `@name`, and a misspelled name close to a field's suggests `@name`.
Among declarations, where a call can only run a macro, an unknown name is an
undefined macro.

## Example

```wid
def main
  counter = 1
  counter += 1
  puts countr
end
```

```text
error[E0201]: undefined name `countr`
 --> main.wid:4:8
  |
4 |   puts countr
  |        ^^^^^^ not found in this scope
help: a similar name exists: `counter`
  |   puts counter
  = see `wid explain E0201`
```

## How to fix

- Fix the spelling. The help shows the closest name in scope, if there is
  one.
- Assign the variable before reading it. A variable assigned inside an `if`,
  a loop or a block exists only until that block's `end`; assign it before
  the block to use it afterwards.
- For a name from another package, import the package and qualify the name:
  `import "./physics"`, then `physics.step(…)`.
- A method of a type is called on a value (`ball.update(dt)`). Only inside
  that type's methods does a bare name call it on `self`.
- Inside a method, read a field of `self` with `@name`: `@hp` means
  `self.hp`. A bare name is a variable or a method call, never a field.

```wid
def main
  counter = 1
  counter += 1
  puts counter
end
```

## A field read without `@`

```wid
struct Player
  hp: Int = 100
  def score -> Int = hp * 2
end

def main
  p Player.new.score
end
```

```text
error[E0201]: undefined name `hp`
 --> main.wid:3:22
  |
3 |   def score -> Int = hp * 2
  |                      ^^ not found in this scope
  = note: `hp` is a field of `Player`; a bare name in a method is a variable or a method call, never a field
help: read the field with `@hp`, which means `self.hp`
  |   def score -> Int = @hp * 2
  = see `wid explain E0201`
```

Inside a method, `@name` means `self.name`, and it reaches the fields that a
`using` field promotes too. A bare name never reads a field: it is a local
variable, or a call of a method of `self`. Assigning to a bare name, like
`hp = 3`, declares a new local variable and leaves the field alone. Calling
the field, `hp()`, gets the same fix, `@hp`; a field that holds a proc is
called with `@on_hit.call(…)`. A name close to a field's, like `hpp`,
suggests `@hp`.

```wid
struct Player
  hp: Int = 100
  def score -> Int = @hp * 2
end

def main
  p Player.new.score
end
```

## An undefined macro among declarations

```wid
macro def describer(name: Symbol) -> Code
  quote do
    def describe -> String = "#{@#{name}}"
  end
end

struct Player
  hp: Int = 100
  describe :hp
end

def main
  p Player.new
end
```

```text
error[E0201]: undefined macro `describe`
  --> main.wid:9:3
   |
 9 |   describe :hp
   |   ^^^^^^^^ no macro with this name is in scope
   = note: a call among declarations runs a macro, and the declarations it generates take the call's place
help: a macro with a similar name exists: `describer`
   |   describer :hp
   = see `wid explain E0201`
```

A call among declarations runs a macro, and the declarations it generates
take the call's place. Fix the macro's name, or import the package that
defines it and qualify the call (`lib.describer :hp`):

```wid
macro def describer(name: Symbol) -> Code
  quote do
    def describe -> String = "#{@#{name}}"
  end
end

struct Player
  hp: Int = 100
  describer :hp
end

def main
  puts Player.new.describe
end
```

## A misspelled macro call in a method

```wid
macro def counter(name: Symbol) -> Code
  quote do
    #{name} = 0
  end
end

def main
  countr :hits
  hits += 1
  puts hits
end
```

```text
error[E0201]: undefined method `countr`
 --> main.wid:8:3
  |
1 | macro def counter(name: Symbol) -> Code
  |           ------- the macro `counter` is defined here
...
8 |   countr :hits
  |   ^^^^^^ not found in this scope
help: a macro with a similar name exists: `counter`
  |   counter :hits
  = see `wid explain E0201`
```

When the name is close to a macro's, the help offers the macro. The call was
probably meant to run it, so the variables its code would have declared
(`hits` here) aren't reported as undefined too; the same holds for a call
standing alone on a line with a symbol argument whose name is close to
nothing else. Fix the macro's name:

```wid
macro def counter(name: Symbol) -> Code
  quote do
    #{name} = 0
  end
end

def main
  counter :hits
  hits += 1
  puts hits
end
```

## `attr_reader`, `attr_writer` and `attr_accessor`

Ruby exposes a field through accessor methods. Wid has no accessor macros:
fields are always public, so code reads and writes them directly, and a
method can't share a field's name (E0202).

```wid
struct Hero
  hp: Int = 100
  attr_accessor :hp
end

def main
  hero = Hero.new
  hero.hp -= 10
  puts hero.hp
end
```

```text
error[E0201]: undefined macro `attr_accessor`
 --> main.wid:3:3
  |
3 |   attr_accessor :hp
  |   ^^^^^^^^^^^^^ no macro with this name is in scope
  = note: a call among declarations runs a macro, and the declarations it generates take the call's place
  = note: Wid has no accessor macros: fields are always public, and code reads and writes them directly
help: remove the call and use the field itself, like `hero.hp` or `@hp` in a method
  = see `wid explain E0201`
```

Remove the call. `hero.hp` reads the field and `hero.hp = 3` writes it:

```wid
struct Hero
  hp: Int = 100
end

def main
  hero = Hero.new
  hero.hp -= 10
  puts hero.hp
end
```
