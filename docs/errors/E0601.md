# E0601: package to document or query not found

<!-- command: doc core:strngs -->
<!-- fix-command: doc core:strings -->

`wid doc` documents a package, or one symbol of it. The package is its first
argument: a directory of `.wid` files (`.` when none is named), a single
`.wid` file with `-file`, or a collection path such as `core:fmt` or
`vendor:raylib`. This error says that package can't be found:

- the directory doesn't exist, or holds no `.wid` files;
- the argument is a `.wid` file, but `-file` isn't given;
- the collection (`core`, `vendor`, or one defined with
  `-collection:name=path`) doesn't exist or has no such package;
- no package was named, and the current directory holds none.

A single argument is the package when it names an existing directory or file
or contains `:`; otherwise it is a symbol of the package in `.`. So
`wid doc shapez` run outside a package says both what it tried as a package
and why the symbol reading failed: there is no package in `.` to look it up
in.

`wid query` reports the same error for the package it reads: the one in
`.`, or the one `-in:` names (`wid query outline -in:core:strngs`). With
`-file`, `-in:` names the file. Like every `wid query` diagnostic, it is
printed as JSON on stderr, and its fixes edit the command line
`wid query …`.

## Example

Running `wid doc core:strngs`:

```text
error[E0601]: package `core:strngs` not found
 --> command line:1:9
  |
1 | wid doc core:strngs
  |         ^^^^^^^^^^^ no package with this path
  = note: the packages there are `core:builtin`, `core:c`, `core:fmt`, `core:math`, `core:mem`, `core:os`, `core:strings` and `core:testing`
help: a similar package exists: `core:strings`
  | wid doc core:strings
  = see `wid explain E0601`
```

## How to fix

- Fix the path. The help suggests a package with a similar name, and for a
  collection the note lists its packages.
- A path is relative to the directory you run `wid doc` in.
- To document one file, add `-file`: `wid doc tools/gen.wid -file`.
- To document a symbol of the package you are in, name only the symbol:
  `wid doc Ball.update`, or name the package first: `wid doc . Ball.update`.

Running `wid doc core:strings` shows the package.
