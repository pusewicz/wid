# E0203: variable is never read

A variable is assigned but its value is never used. In Wid this is an error,
not a warning: an unused variable is usually a typo, a forgotten step or
leftover code. Loop variables (`for i in …`) and block parameters (`|x|`)
count as variables too. Method parameters are exempt, and so is any name that
starts with `_`. A variable whose value or type is itself an error (`x = )`,
`y: Nope = 3`) isn't reported: fix that error first.

## Example

```wid
def main
  total = 0
  _ignored = 1
end
```

```text
error[E0203]: `total` is assigned but never read
 --> main.wid:2:3
  |
2 |   total = 0
  |   ^^^^^ this value is never used
help: if this is intentional, prefix the name with an underscore
  |   _total = 0
  = see `wid explain E0203`
```

`_ignored` is not reported because of its leading underscore.

## How to fix

- Use the value. Often the name is misspelled where it is read; look for an
  E0201 next to this error.
- If the value is not needed, delete the assignment.
- If you keep it on purpose, prefix the name with `_`: `for _i in 0...3`.
- To drop a call's result, including an `Error`, assign it to `_`:
  `_ = save(path)`.

```wid
def main
  total = 0
  total += 5
  puts total
end
```

## Writing a field or an element

Writing a field or an element of a variable (`ship.hp = 9`, `cells[0] = 1`)
changes the variable but doesn't read it, so a variable that is only ever
written that way is reported too, with a label on the first such write:

```wid
def main
  cells: [3]Int = {}
  cells[0] = 1
end
```

```text
error[E0203]: `cells` is assigned but never read
 --> main.wid:2:3
  |
2 |   cells: [3]Int = {}
  |   ^^^^^ this value is never used
3 |   cells[0] = 1
  |   -------- this writes into `cells` but doesn't read it
help: if this is intentional, prefix the name with an underscore
  |   _cells: [3]Int = {}
  = see `wid explain E0203`
```

Writing through a pointer reads the pointer (`ptr = &ship`, then
`ptr.hp = 9`), and so does writing an element of a slice or a dynamic
array, whose elements live elsewhere.

A loop variable is a copy of each element, so writing its fields changes
nothing. The fix binds the elements by reference, so the writes reach them:

```wid
struct Ship
  hp: Int
end

def main
  ships = [Ship.new, Ship.new]
  for s in ships
    s.hp = 1
  end
  p ships
end
```

```text
error[E0203]: `s` is assigned but never read
 --> main.wid:7:7
  |
7 |   for s in ships
  |       ^ this value is never used
8 |     s.hp = 1
  |     ---- this changes a copy of an element of `ships`, not the element
  = note: `for s in …` binds a copy of each element
help: to change the elements of `ships`, bind them by reference with `&`
  |   for &s in ships
  = see `wid explain E0203`
```
