# E0331: operator that can't be defined

A type defines `==` and `<=>`, and the other comparisons come from them:
`a != b` is `!(a == b)`, and `a < b`, `a <= b`, `a > b` and `a >= b`
compare `a <=> b` with 0. So `!=`, `<`, `<=`, `>` and `>=` can't be defined
themselves, as methods, package-level `def`s or `overload` sets: a type's
comparisons always agree with each other. Nor can `!`: `!x` is true when `x`
is `nil` or `false`, for every type.

The operators a type can define are `+ - * / % **`, the bitwise
`& | ~ << >>`, unary `-` and `~`, `==`, `<=>`, `[]` and `[]=`; `+=`-style
forms come from the binary ones.

## Example

```wid
struct Version
  major: Int
  minor: Int

  def <(other: Version) -> Bool = @major < other.major
  def !=(other: Version) -> Bool = @major != other.major
end

def main
  a = Version.new(1, 2)
  b = Version.new(2, 0)
  p a < b
  p a != b
end
```

## How to fix

- Define `<=>`, returning a negative `Int` when `self` comes first, 0 when
  the two are equal and a positive one when `other` comes first. `<`, `<=`,
  `>` and `>=` then work, and so do `min`, `max` and `sort!`.
- Define `==` for `!=`. Without one, `==` and `!=` compare the fields.
- When the type already defines `==` or `<=>`, remove the other definition:
  the comparison comes from it already.
- For `!`, give the method a name and call it by that name.

```wid
struct Version
  major: Int
  minor: Int

  def <=>(other: Version) -> Int = @major <=> other.major
  def ==(other: Version) -> Bool = @major == other.major
end

def main
  a = Version.new(1, 2)
  b = Version.new(2, 0)
  p a < b
  p a != b
end
```
