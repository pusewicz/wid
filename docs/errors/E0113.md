# E0113: struct literal syntax

Odin, Go, Rust and Zig build a struct with a literal written after its type,
like `Vec2{x: 1.0, y: 2.0}`. Wid has no struct literal syntax: a struct is
built by calling `new` on its type, which takes the fields by name or in
declaration order, like any call. Fields that aren't given get their declared
default, or zero.

The compiler reads the braces as the arguments of that `new` call, so the
value still has the struct's type and the code after it is checked normally.
Odin's `Vec2{x = 1.0}` is read the same way, as `x: 1.0`, and so is
`Vec2 { x: 1.0 }`, with a space before the `{` as Rust and Go write it: a
constant (`Vec2`, `geo.Vec2`) never takes a block, so a `{` after it on the
same line can only be this mistake.

## Example

```wid
struct Vec2
  x: F64
  y: F64
end

def main
  origin = Vec2{x: 0.0, y: 0.0}
  p origin
end
```

```text
error[E0113]: Wid has no struct literal syntax
 --> main.wid:7:12
  |
7 |   origin = Vec2{x: 0.0, y: 0.0}
  |            ^^^^^ structs are built with `new`: `Vec2.new(…)`
  = note: `new` takes the fields by name or in order; the ones not given get their default or zero
help: call `Vec2.new` with the fields as arguments
  |   origin = Vec2.new(x: 0.0, y: 0.0)
  = see `wid explain E0113`
```

## How to fix

- Call `new` on the type, with the fields as arguments:
  `Vec2.new(x: 0.0, y: 0.0)`, or in order, `Vec2.new(0.0, 0.0)`.
- A generic struct's instance is built the same way:
  `Pool(Int, 4).new`.
- For a value with every field zero, `Vec2.new` takes no arguments, and `{}`
  works where the type is known: `origin: Vec2 = {}`.

```wid
struct Vec2
  x: F64
  y: F64
end

def main
  origin = Vec2.new(x: 0.0, y: 0.0)
  p origin
end
```
