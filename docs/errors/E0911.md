# E0911: spliced value doesn't fit its place

A macro builds code with `quote do … end`, and each `#{}` splice in it is
replaced by a value when the macro runs. What a value turns into depends on
its type, and it has to fit where the splice is:

- `Code` is the code itself: one expression where a value goes, any
  statements alone on a line.
- `[]Code` is a list: statements alone on a line, or several call arguments
  or array elements.
- `Symbol` is a name: of a method, field, parameter, variable or type, or an
  identifier in an expression. `:#{name}` is a symbol literal.
- `Type` is a type where a type goes, and a type used as a value (like
  `#{t}.new(…)`) elsewhere.
- Numbers, `Bool`s and strings are literals.

The error is reported at the macro call, because the value comes from the
call's arguments, and marks the splice in the `quote`.

A `quote` can splice only those types; splicing anything else is reported in
the macro itself, with the same code.

## Example

The macro names a method after a `Type`, but a method's name is a name:

```wid
macro def define(t: Type) -> Code
  quote do
    def #{t} = 2
  end
end

def main
  define Int
end
```

```text
error[E0911]: the macro `define` splices a `Type` where a name goes
 --> main.wid:8:3
  |
8 |   define Int
  |   ^^^^^^^^^^ `define` expands here
 ::: main.wid:3:9
  |
3 |     def #{t} = 2
  |         ---- this splice is a `Type`
help: splice a `Symbol` where a name goes; `"text".to_sym` makes one from a string
  = see `wid explain E0911`
```

## How to fix

Splice a value of the kind the place takes. Here the macro takes the name as
a `Symbol`, which the call writes as a symbol literal:

```wid
macro def counter(name: Symbol) -> Code
  quote do
    #{name} = 0
  end
end

def main
  counter :hits
  hits += 1
  puts hits
end
```

When code needs a value but the `Code` holds statements, give the code a
value at its end and splice it alone on a line, where statements go.

## A splice as an assignment target

A splice on the left of `=`, of a compound assignment like `+=` or `||=`,
or among the targets of `a, b = …`, must give something that can hold a
value: a variable's name (a `Symbol`), or `Code` that is a variable, a
field (`@hp`, `ball.hp`), an element (`grid[i]`) or a dereference (`p^`).
A capitalized name declares a constant among declarations, but in a method
it is a constant, which can't be assigned; that error points at the name
where the call writes it. A number, string, `Bool` or `Type`, and code such
as a call or a literal, can't be assigned to either:

```wid
macro def reset(n: Int) -> Code
  quote do
    #{n} = 0
  end
end

def main
  reset 3
end
```

```text
error[E0911]: the macro `reset` splices the integer `3` where an assignment target goes
 --> main.wid:8:3
  |
8 |   reset 3
  |   ^^^^^^^ `reset` expands here
 ::: main.wid:3:5
  |
3 |     #{n} = 0
  |     ---- this splice is the integer `3`, which can't be assigned to
help: splice something that can be assigned to: a variable's name as a `Symbol` (a parameter like `name: Symbol`, called like `reset :count`), or `Code` for a field or an element (`@hp`, `ball.hp`, `grid[i]`)
  = see `wid explain E0911`
```

Take the variable's name as a `Symbol` instead, as `counter` does above, or
take `Code` for a field or an element.
