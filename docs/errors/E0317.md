# E0317: two definitions share a name

Two methods in the same scope have the same name. Wid has no implicit
overloading: a name refers to exactly one definition, so every call site and
every error points at one place. To call several methods through one name,
give each its own name and group them in an explicit `overload` set, like an
Odin proc group.

## Example

```wid
def scale(x: Int) -> Int
  x * 2
end

def scale(x: F32) -> F32
  x * 2.0
end

def main
end
```

```text
error[E0317]: `scale` is defined twice
 --> main.wid:5:5
  |
1 | def scale(x: Int) -> Int
  |     ----- first definition
...
5 | def scale(x: F32) -> F32
  |     ^^^^^ second definition
  = note: Wid has no implicit overloading: every definition needs its own name
help: rename them (for example `scale_int` and `scale_f32`) and group them with `overload :scale, :scale_int, :scale_f32`
  = see `wid explain E0317`
```

## How to fix

- Rename each method after the type it handles, then declare the set:
  `overload :scale, :scale_int, :scale_f32`. `scale(x)` then resolves to the
  member whose parameter types match `x` (see E0316 for the exact rules).
- If the two definitions are the same method written twice, delete one.
- If each belongs to a type, make them methods of those types (inside
  `struct … end` or `extend … end`). Methods of different types may share a
  name.
- Operators work the same way: name the methods (`mul_f32`, `mul_vec2`) and
  declare `overload :*, :mul_f32, :mul_vec2`. For an operator whose left operand
  is not your type, like `F32 * Vec2`, define a package-level
  `def scale_vec(s: F32, v: Vec2) -> Vec2` and group it with
  `overload :*, :scale_vec`.

```wid
def scale_int(x: Int) -> Int
  x * 2
end

def scale_f32(x: F32) -> F32
  x * 2.0
end

overload :scale, :scale_int, :scale_f32

def main
  n = 3
  f: F32 = 1.5
  puts scale(n)
  puts scale(f)
end
```

## A method declared by each call of a macro

```wid
macro def helpers -> Code
  quote do
    def dup -> Int = 1
  end
end

helpers()
helpers()

def main
  p dup
end
```

```text
error[E0317]: `dup` is defined twice
 --> main.wid:3:9
  |
3 |     def dup -> Int = 1
  |         ^^^ each expansion of `helpers` defines `dup` here
 ::: main.wid:7:1
  |
7 | helpers()
  | --------- first expansion here
8 | helpers()
  | --------- second expansion here
  = note: a macro's code is the same for every call, so a name it declares as written is declared again by each call of `helpers`
help: call `helpers` once, or take the name as a `Symbol` parameter and splice it where it is declared (`#{name}`), so each call declares its own
  = see `wid explain E0317`
```

Each call of `helpers` declares `dup` again, so the error shows the `def`
once, with both calls, and suggests calling the macro once or splicing the
method's name from a `Symbol` parameter (`def #{name} -> Int = 1`) so each
call declares its own.
