# E0307: operator not defined for these types

An operator is applied to types it is not defined for. Built-in arithmetic
and comparison need both operands to have the same type: Wid does not promote
`Int` to `F32`, or `I32` to `I64`. Arithmetic works on numbers, `<`-style
comparisons on numbers, runes and strings, and `==` on most values, including
structs whose fields are all comparable. Anything else needs an operator
method. `String` has no `+`.

The ordering comparisons `<`, `<=`, `>` and `>=` on your own type call its
`<=>` and compare the result with 0, and `!=` negates its `==`. So a type
gets them by defining `<=>` or `==`, and the same code reports a `<=>` that
doesn't return an integer or an `==` that doesn't return `Bool`, when a
comparison derived from it is used.

The same code reports indexing a value that has no `[]` method, `<=>` on
values that can't be ordered, and a unary operator on the wrong type.

## Example

```wid
struct Money
  cents: Int
end

def main
  a: F32 = 1.0
  b = 2
  puts a + b
  s = "x"
  puts s + s
  puts Money.new(1) < Money.new(2)
end
```

## How to fix

- Convert one operand so the types match: `a + b.to(F32)`, or declare
  `b: F32 = 2`.
- Build strings with interpolation: `"#{s}#{s}"`.
- For your own types, define the operator as a method: `def +(o: Vec2) -> Vec2`.
  `+=`-style forms then work automatically.
- For `<`, `<=`, `>` and `>=`, define `def <=>(o: Money) -> Int`, returning a
  negative number when `self` comes first, 0 when equal and a positive one
  when `o` does. For `!=`, define `==`.
- If the left operand is not your type (`F32 * Transform`), define the operator
  at package level: `def *(s: F32, t: Transform) -> Transform`.
- For several right-hand types, use an explicit set:
  `overload :*, :apply, :compose`.

```wid
struct Money
  cents: Int

  def <=>(o: Money) -> Int = @cents <=> o.cents
end

def main
  a: F32 = 1.0
  b = 2
  puts a + b.to(F32)
  s = "x"
  puts "#{s}#{s}"
  puts Money.new(1) < Money.new(2)
end
```
