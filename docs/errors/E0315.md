# E0315: wrong generic arguments

A generic type is used without its arguments, with the wrong number of them,
or with the wrong kind of argument. A generic struct such as
`struct Pool($T, $N: Int)` takes one argument per parameter, in order: a type
for `$T`, and a constant integer for `$N: Int`, so `Pool(64, 8)` and
`Pool(F32, F32)` are both errors. A type that is not generic takes no
arguments.

The same code reports a generic value argument that is not a constant, a call
to a generic method where nothing determines `$T`, and a generic method or
struct that keeps instantiating itself with ever larger types.

## Example

```wid
struct Pool($T, $N: Int)
  items: [N]T
  count: Int
end

def main
  bullets: Pool = {}
  p bullets
end
```

```text
error[E0315]: `Pool` needs type arguments
 --> main.wid:7:12
  |
7 |   bullets: Pool = {}
  |            ^^^^ write it like `Pool(T, N)`
  = see `wid explain E0315`
```

With the wrong number of arguments, as in `Pool(F32)`, the message reads
`` `Pool` takes 2 type arguments `` and says how many were given.

## How to fix

- Pass every parameter, in order: `Pool(F32, 64)`.
- Pass a type where the parameter is `$T`, and a constant integer where it
  is `$N: Int`: a literal, a named constant (`Pool(F32, MAX)`), constant
  arithmetic (`Pool(F32, MAX * 2)`) or a `comptime` result. A runtime
  variable cannot be a generic argument; declare a package-level constant
  instead. A float constant converts with `.to(Int)`: `Pool(F32, RATE.to(Int))`.
- Remove the arguments from a type that is not generic.
- Generic methods take no explicit type arguments: `$T` is inferred from the
  call's arguments, so pass an argument whose type determines it.

```wid
struct Pool($T, $N: Int)
  items: [N]T
  count: Int
end

def main
  bullets: Pool(F32, 64) = {}
  p bullets
end
```
