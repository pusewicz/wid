# E0914: enum member named like a macro

In an `enum` body a name alone on a line declares a member, even when a macro
of that name is visible there. A macro called among an enum's declarations
without arguments therefore needs parentheses: `helpers()`. A member written
without a value whose name is also a macro's is reported, since the line was
most likely meant to call the macro; otherwise the methods the macro
generates would silently be missing.

Until the line is fixed, the enum's missing methods aren't reported where
they are used, since they may be ones the macro would generate.

## Example

```wid
macro def helpers -> Code
  quote do
    def describe -> String = "a color"
  end
end

enum Color
  red
  helpers
end

def main
  c: Color = :red
  puts c.describe
end
```

```text
error[E0914]: `helpers` names a macro, but alone on a line in an enum it declares a member
  --> main.wid:9:3
   |
 1 | macro def helpers -> Code
   |           ------- `helpers` is a macro
...
 9 |   helpers
   |   ^^^^^^^ this declares the member `:helpers` of `Color`
   = note: in an `enum` body a name alone on a line is a member, so a macro without arguments is called with `()` there
help: call the macro
   |   helpers()
help: to keep the member, write its value: `helpers = 1`
   = see `wid explain E0914`
```

## How to fix

- To call the macro, add `()`, as the fix does.
- To keep the member, write its value (`helpers = 1`): a member with a value
  is never a macro call. Renaming the member or the macro works too.

```wid
macro def helpers -> Code
  quote do
    def describe -> String = "a color"
  end
end

enum Color
  red
  helpers()
end

def main
  c: Color = :red
  puts c.describe
end
```
