# E0914: enum member named like a macro

In an `enum` body a name alone on a line is read as a member, even when a
macro of that name is visible there. A macro called among an enum's
declarations without arguments therefore needs parentheses: `helpers()`. A
name alone on a line that is also a macro's is reported as this error rather
than as a lowercase member (E0114), since the line was most likely meant to
call the macro; otherwise the methods the macro generates would silently be
missing.

Until the line is fixed, the enum's missing methods aren't reported where
they are used, since they may be ones the macro would generate.

## Example

```wid
macro def helpers -> Code
  quote do
    def describe -> String = "a color"
  end
end

enum Color
  Red
  helpers
end

def main
  c: Color = .Red
  puts c.describe
end
```

```text
error[E0914]: `helpers` names a macro, but alone on a line in an enum it is read as a member
  --> main.wid:9:3
   |
 1 | macro def helpers -> Code
   |           ------- `helpers` is a macro
...
 9 |   helpers
   |   ^^^^^^^ alone on a line, this is read as a member of `Color`
   = note: in an `enum` body a name alone on a line is a member, so a macro without arguments is called with `()` there
help: call the macro
   |   helpers()
help: to declare a member, name it like a constant: `Helpers`, or `Helpers = 1`
   = see `wid explain E0914`
```

## How to fix

- To call the macro, add `()`, as the fix does.
- To declare a member instead, name it like a constant (`Helpers`, or
  `Helpers = 1`): members start with a capital letter, and macros never do.

```wid
macro def helpers -> Code
  quote do
    def describe -> String = "a color"
  end
end

enum Color
  Red
  helpers()
end

def main
  c: Color = .Red
  puts c.describe
end
```
