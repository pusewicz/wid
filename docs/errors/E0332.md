# E0332: type can't be a map key

A map finds a key by hashing it and comparing it with the built-in `==`, so
a key type is one whose `==` is the built-in one: a number, rune, bool,
enum, pointer or string, or a struct, fixed array, tuple or optional of
them. Two keys that are `==` find the same entry: `0.0` and `-0.0` are one
key, a string is compared by its text, and padding doesn't count.

These can't be keys:

- a slice or a dynamic array, which have no `==` (they view or own memory
  that can change under the map), a union and a proc, nor a struct, array
  or optional that holds one;
- a struct that defines its own `==`: the map would compare every field,
  and two keys your `==` calls equal could find different entries.

In generic code, the key is checked for each type the code is used with,
and the error points at the call or the instance that uses it.

## Example

```wid
struct Player
  name: String
  scores: []Int
end

struct Money
  cents: Int
  note: String

  def ==(other: Money) -> Bool = @cents == other.cents
end

def main
  wins = map[Player]Int.new
  defer free(wins)
  prices = map[Money]String.new
  defer free(prices)
  p wins.size + prices.size
end
```

## How to fix

- Key the map by what identifies a value: a player by their name, an amount
  by its cents.
- Use a fixed array (`[4]Int`) or a `String` in place of a slice.

```wid
struct Player
  name: String
  scores: []Int
end

struct Money
  cents: Int
  note: String

  def ==(other: Money) -> Bool = @cents == other.cents
end

def main
  wins = map[String]Int.new
  defer free(wins)
  prices = map[Int]String.new
  defer free(prices)
  p wins.size + prices.size
end
```
