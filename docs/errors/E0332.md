# E0332: operator that derives from another can't be defined

A type defines `==` and `<=>`, and Wid derives the other comparisons from
them: `a != b` is `!(a == b)`, and `a < b`, `a <= b`, `a > b` and `a >= b`
compare `a <=> b` with 0. So `!=`, `<`, `<=`, `>` and `>=` can't be defined
themselves, as a method, a package-level function or an `overload` set:
two definitions of one question could give different answers, like
`a < b` and `b > a` both true.

`<=>` returns an integer: negative when `self` comes first, 0 when the two
are equal, and positive when `other` does. Comparing two fields with `<=>`
already gives that, and a key made of several fields compares the next one
when the first gives 0.

`!` can't be defined either. It negates a `Bool` and isn't a method, so a
yes-or-no question about a value is a `?` method, like `empty?`, written
`!x.empty?`.

The fix renames the operator. The return type and the body still have to
change to match, so it is a start rather than the whole fix.

## Example

```wid
struct Money
  cents: Int

  def <(o: Money) -> Bool = @cents < o.cents
end

def main
  puts Money.new(1) < Money.new(2)
end
```

## How to fix

- Define `<=>` and let it give all four comparisons:
  `def <=>(o: Money) -> Int = @cents <=> o.cents`.
- For `!=`, define `==` returning `Bool`; `!=` is its negation.
- For `!`, write a `?` method and negate its result.

```wid
struct Money
  cents: Int

  def <=>(o: Money) -> Int = @cents <=> o.cents
end

def main
  puts Money.new(1) < Money.new(2)
end
```
