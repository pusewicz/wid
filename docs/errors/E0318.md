# E0318: proc captures a local variable

A proc literal (`->(x: Int) -> Int { … }`) reads a local variable or parameter
of the method around it. A proc is a plain function pointer with no hidden
state, so it has nowhere to keep a captured variable alive, and Wid will not
allocate a closure behind your back. Blocks are different: they are inlined
into the method they are passed to, so they can use any local.

## Example

```wid
def main
  bonus = 10
  add_bonus = ->(x: Int) -> Int { x + bonus }
  puts add_bonus(5)
end
```

```text
error[E0318]: this proc uses `bonus` from the code around it
 --> main.wid:3:39
  |
3 |   add_bonus = ->(x: Int) -> Int { x + bonus }
  |                                       ^^^^^ procs cannot capture local variables
  = note: a proc is a plain function pointer; it has nowhere to keep `bonus` alive
help: pass the value as a parameter, use a block (`do |x| … end`) when the callee yields, or store it in a struct the proc receives
  = see `wid explain E0318`
```

## How to fix

- Pass the value as a proc parameter: `->(x: Int, extra: Int) -> Int { … }`.
- If the callback runs right away, pass a block to a method with a `&blk`
  parameter instead. Blocks use locals freely and allocate nothing.
- For a callback that is stored and called later, put the state in a struct
  and pass a pointer to it as a parameter.
- Constants are not locals. A proc may read a package-level `BONUS = 10`.

```wid
def main
  bonus = 10
  add = ->(x: Int, extra: Int) -> Int { x + extra }
  puts add(5, bonus)
end
```
