# E0320: `yield` in a method without a block parameter

`yield` runs the block passed to the current method, so the method must
declare one. Wid has no implicit block as Ruby does. The block parameter and
its type, `&blk: block(T) -> R`, are part of the signature, so callers and the
compiler know what the block receives and returns. The fix adds a block
parameter whose types match the values the `yield` passes. Procs cannot take
blocks, so `yield` inside a proc literal is the same error; pass the code to
run as a proc parameter instead.

## Example

```wid
def each_cell(w: Int, h: Int)
  for y in 0...h
    for x in 0...w
      yield x, y
    end
  end
end

def main
  each_cell(2, 2) { |x, y| puts x + y }
end
```

```text
error[E0320]: `each_cell` has no block parameter to `yield` to
 --> main.wid:4:7
  |
4 |       yield x, y
  |       ^^^^^^^^^^ nothing to yield to
help: declare the block in the signature: `&blk: block(Int, Int)`
  | def each_cell(w: Int, h: Int, &blk: block(Int, Int))
  = see `wid explain E0320`
```

Declaring the block parameter fixes both errors.

## How to fix

- Add a block parameter whose types match what you yield:
  `&blk: block(Int, Int)`. Add `-> R` if the method uses the block's result.
- If the method should call a stored callback instead, take a `proc` parameter
  and call it: `f: proc(Int, Int)`, then `f(x, y)`.

```wid
def each_cell(w: Int, h: Int, &blk: block(Int, Int))
  for y in 0...h
    for x in 0...w
      yield x, y
    end
  end
end

def main
  each_cell(2, 2) { |x, y| puts x + y }
end
```
