# E0202: duplicate definition

The same name is declared twice where it must be unique. That covers:

- two constants or types with one name in a package;
- a field or enum member listed twice, a union variant listed twice, or a
  field and a method of one type with the same name;
- two imports under one name, a module included twice, or a method listed
  twice in one `overload` set;
- `def self.new` in a struct, because `Type.new(…)` is the builtin
  constructor;
- a typed declaration (`x: T = …`) of a variable that already exists;
- a type named like a builtin type (`Int`, `String`, `Bool`, `RawPtr`, …).
  Only the predeclared library types `Context`, `Allocator`, `AllocMode`,
  `Location` and `Logger` can be declared again, and inside that package the
  name then means the package's own type;
- a name a package declares that its `cimport` without `as:` also adds,
  or that two such `cimport`s both add.

Two methods with the same name are reported as E0317 instead, because Wid
has no implicit overloading.

## Example

```wid
def main
  speed: F32 = 1.0
  speed: F32 = 2.0
  puts speed
end
```

```text
error[E0202]: `speed` is already declared
 --> main.wid:3:3
  |
2 |   speed: F32 = 1.0
  |   ----- first declared here
3 |   speed: F32 = 2.0
  |   ^^^^^ declared again here
help: assign to the existing variable with `=` instead of declaring it again
  = see `wid explain E0202`
```

## How to fix

- To change a variable, assign it with plain `=`. A type annotation always
  declares a new variable.
- If you need both, rename one of them.
- If two imports end in the same name, rename one with `as:`:
  `import "./ui/text", as: :ui_text`.
- Remove the repeated field, enum member, variant, `include` or set member.
- Give a custom constructor its own name, such as `def self.create`.
- When a `cimport` without `as:` brings a name the package already has,
  rename the C declaration with `names: {CName: :wid_name}`, or give the
  `cimport` a namespace with `as:`.

```wid
def main
  speed: F32 = 1.0
  speed = 2.0
  puts speed
end
```

## A name declared by each call of a macro

```wid
macro def limits -> Code
  quote do
    LIMIT = 1
  end
end

limits()
limits()

def main
  p LIMIT
end
```

```text
error[E0202]: `LIMIT` is defined twice
 --> main.wid:3:5
  |
3 |     LIMIT = 1
  |     ^^^^^ each expansion of `limits` defines `LIMIT` here
 ::: main.wid:7:1
  |
7 | limits()
  | -------- first expansion here
8 | limits()
  | -------- second expansion here
  = note: a macro's code is the same for every call, so a name it declares as written is declared again by each call of `limits`
help: call `limits` once, or take the name as a `Symbol` parameter and splice it where it is declared (`#{name}`), so each call declares its own
  = see `wid explain E0202`
```

A macro's code is the same for every call, so a name it declares as written
is declared again by each call. The error shows the line of the `quote` once,
with both calls. Call the macro once, or take the name as a `Symbol`
parameter and splice it, so each call declares its own:

```wid
macro def limit(name: Symbol) -> Code
  quote do
    #{name} = 1
  end
end

limit :LIMIT
limit :OTHER_LIMIT

def main
  p LIMIT, OTHER_LIMIT
end
```
