# E0702: C compiler failed

Wid compiles to C23 and then runs the host C compiler (clang 19 or newer, or
gcc 15 or newer) to build the program. That step failed: either the compiler
could not be started, or it rejected the code. Besides Wid's generated C,
`wid build` and `wid run` also compile and link the `.c` files in the package,
so the problem is often there. `wid check` stops before this step and never
reports E0702.

Each source is compiled on its own, then everything is linked, so the message
says which step failed: one of your `.c` or `.cpp` files (its name is in the
message), the generated C (a Wid bug; a note says where the generated C was
kept), or linking (often a C function declared with `@[extern]` that nothing
defines). The C compiler's own output follows in a note. `.cpp` files are
compiled as C++20 with the C++ compiler that matches the C one (`clang++`,
`g++-16`; `WID_CXX` or `CXX` choose another), and the program is then linked
as C++. When the compiler cannot be started at all, the error reads
``cannot run the C compiler `clang-99`: …`` and suggests installing one or
choosing it with `-cc:path` or `WID_CC`. When it runs but is too old for C23
(it rejects `-std=c23`, or lacks `<stdckdint.h>` or `#embed`), the error says
that the compiler doesn't support C23 and shows the version it reports.

## Example

A package directory `game` whose C file is missing a semicolon:

```wid
@[extern("fm_square")]
def square(x: I32) -> I32
end

def main
  puts square(7)
end
```

`fast_math.c`:

```c
#include <stdint.h>

int32_t fm_square(int32_t x) { return x * x }
```

Running `wid build` in `game`, with clang as `cc`:

```text
error[E0702]: `fast_math.c` does not compile
  = note: fast_math.c:3:44: error: expected ';' after return statement
              3 | int32_t fm_square(int32_t x) { return x * x }
                |                                            ^
                |                                            ;
          1 error generated.
help: fix the error in fast_math.c; it is compiled with every build of its package
  = see `wid explain E0702`
```

## A C compiler without C23

`wid run main.wid -file` on a machine where `cc` is gcc 13, with neither
`WID_CC` nor `CC` set:

```console
error[E0702]: the C compiler `cc` doesn't support C23
  = note: cc: error: unrecognized command-line option '-std=c23'; did you mean '-std=c2x'?
  = note: `cc --version` says: cc (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0
  = note: Wid compiles to C23, which needs clang 19 or newer, or gcc 15 or newer
help: install clang 19+ or gcc 15+, and choose it with `-cc:path` (like `-cc:gcc-15`) or the WID_CC variable
  = see `wid explain E0702`
```

The generated C is fine; the compiler is older than the C23 that Wid
generates. clang before 18 rejects `-std=c23` too, while clang 18 and gcc 14
lack `#embed`, so they fail on programs that `embed` a file; a compiler
without `<stdckdint.h>` is reported the same way. Install a newer compiler
next to the old one and choose it: for one build with
`wid run main.wid -file -cc:gcc-15`, or for every build with
`WID_CC=gcc-15`.

## How to fix

- Read the C compiler's message. If it points at a `.c` file of your package,
  fix that file.
- If the compiler cannot be run, or doesn't support C23, install clang 19+
  or gcc 15+, and choose it with `-cc:path` or the `WID_CC` environment
  variable (`CC` is read too). Without either, Wid runs `cc`, which is often
  an older gcc.
- For undefined symbols at link time, check that every `@[extern]` name is
  defined in one of the package's `.c` files, or in a library given with
  `link:`.
- If a C23 compiler rejects the generated C, that is a Wid bug. Report it
  with the kept `.c` file. `-keep-c` writes it next to the output even when
  the build succeeds.

`fast_math.c`, fixed:

```c
#include <stdint.h>

int32_t fm_square(int32_t x) { return x * x; }
```
