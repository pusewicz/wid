# E0702: C compiler failed

Wid compiles to C23 and then runs the host C compiler (clang 19 or newer, or
gcc 15 or newer) to build the program. That step failed: either the compiler
could not be started, or it rejected the code. Besides Wid's generated C,
`wid build` and `wid run` also compile and link the `.c` files in the package,
so the problem is often there. `wid check` stops before this step and never
reports E0702.

Each source is compiled on its own, then everything is linked, so the message
says which step failed: one of your `.c` or `.cpp` files (its name is in the
message), the generated C (a Wid bug; a note says where the generated C was
kept), or linking (often a C function declared with `@[extern]` that nothing
defines). The C compiler's own output follows in a note. `.cpp` files are
compiled as C++20 with the C++ compiler that matches the C one (`clang++`,
`g++-16`; `WID_CXX` or `CXX` choose another), and the program is then linked
as C++. When the compiler cannot be started at all, the error reads
``cannot run the C compiler `clang-99`: …`` and suggests installing one or
choosing it with `-cc:path` or `WID_CC`.

## Example

A package directory `game` whose C file is missing a semicolon:

```wid
@[extern("fm_square")]
def square(x: I32) -> I32
end

def main
  puts square(7)
end
```

`fast_math.c`:

```c
#include <stdint.h>

int32_t fm_square(int32_t x) { return x * x }
```

Running `wid build` in `game`, with clang as `cc`:

```text
error[E0702]: `fast_math.c` does not compile
  = note: fast_math.c:3:44: error: expected ';' after return statement
              3 | int32_t fm_square(int32_t x) { return x * x }
                |                                            ^
                |                                            ;
          1 error generated.
help: fix the error in fast_math.c; it is compiled with every build of its package
  = see `wid explain E0702`
```

## How to fix

- Read the C compiler's message. If it points at a `.c` file of your package,
  fix that file.
- If the compiler cannot be run, install clang 19+ or gcc 15+, or choose one
  with `-cc:path` or the `WID_CC` environment variable (`CC` is read too).
- For undefined symbols at link time, check that every `@[extern]` name is
  defined in one of the package's `.c` files, or in a library given with
  `link:`.
- If the generated C is rejected, that is a Wid bug. Report it with the kept
  `.c` file. `-keep-c` writes it next to the output even when the build
  succeeds.

`fast_math.c`, fixed:

```c
#include <stdint.h>

int32_t fm_square(int32_t x) { return x * x; }
```
