# E0401: `Error` result ignored

A statement drops a value of type `Error`, alone or as the last of several
return values, or a union returned as the last of several values (a union can
be nil, so it works as the error value too). Wid has no exceptions: a
fallible function reports failure through its last return value, so dropping
that value would hide the failure. Handle it with `guard`, pass it on, or
discard it explicitly with `_`.

## Example

```wid
def checked_div(a: Int, b: Int) -> (Int, Error)
  return {}, :division_by_zero if b == 0
  return a / b, nil
end

def main
  checked_div(10, 0)
end
```

```text
error[E0401]: the `Error` returned here is ignored
 --> main.wid:7:3
  |
7 |   checked_div(10, 0)
  |   ^^^^^^^^^^^^^^^^^^ this call can fail
help: handle it with `guard … else |err| … end`
help: or discard it explicitly with `_ = …`
  |   _ = checked_div(10, 0)
  = see `wid explain E0401`
```

## How to fix

- Use `guard`. It binds the values before the error for the rest of the scope
  and runs the `else` branch on failure. That branch must leave the scope with
  `return`, `break`, `next` or `panic`.
- In a fallible function, pass the error on: `return {}, err`.
- If failure truly doesn't matter, discard the error with `_`:
  `q, _ = checked_div(10, 2)`, or `_ = save(path)` to drop every value.
  `_` is not a variable: each `_ = …` drops a value of any type.

```wid
def checked_div(a: Int, b: Int) -> (Int, Error)
  return {}, :division_by_zero if b == 0
  return a / b, nil
end

def main
  guard q = checked_div(10, 2) else |err|
    p err
    return
  end
  puts q
end
```
